# 1.4 时延、丢包与吞吐量

> 章级精读：[../study.md#ch1-4](../study.md#ch1-4)  
> 衔接：[1.3 存储转发时延](../1.3_network_core_switching/study.md)（`d ≈ N×(L/R)` 主要对应**传输时延**）

## 本节核心目标

**学会量化网络性能：时延多大、为什么丢包、吞吐量由什么决定。**

---

## 一、四大时延（总时延 = 4 项之和）

**节点总时延**：`D = d_proc + d_queue + d_trans + d_prop`

| 时延 | 英文 | 量级 | 一句话 |
|------|------|------|--------|
| 处理 | Processing | **μs**，常可忽略 | 查表、检查、决策 |
| 排队 | Queuing | **ms**，**最不稳定** | 输出队列里等车，**卡顿主因** |
| 传输（发送） | Transmission | 由 L、R 定 | 把**整包推上链路** |
| 传播 | Propagation | 由距离、介质定 | **1 bit** 在介质里跑多远 |

考试常简化：**D ≈ d_trans + d_prop**（忽略处理/排队）。

---

### 1）处理时延 Processing Delay

- **定义**：路由器/交换机检查分组头部、查转发表、纠错的时间。
- **特点**：**微秒级（μs）**，通常很小可忽略。
- **一句话**：**查表、检查、决策的时间**。

---

### 2）排队时延 Queuing Delay（最关键）

- **定义**：分组在路由器**输出队列**里排队等待发送的时间。
- **特点**：**毫秒级（ms）**，变化最大，**最容易导致卡顿**。
- **流量强度**（与 [1.3](../1.3_network_core_switching/study.md) 一致）：

  **I = La / R**（**L**=分组长度 bit，**a**=到达率 pkt/s，**R**=链路带宽 bps）

  | I | 现象 |
  |---|------|
  | **I < 1** | 排队较短、时延小 |
  | **I → 1** | 排队爆炸、时延剧增 |
  | **I > 1** | 队列无限增长、**必然丢包** |

- **一句话**：**堵车等待时间，网络卡顿主要元凶**。

---

### 3）传输时延（发送时延）Transmission Delay

- **定义**：把**整个分组全部推到链路上**所需时间（≠ 传播！）。
- **公式**：**d_trans = L / R**（**L** bits，**R** bps）
- **特点**：与**分组长度、带宽**有关；**与距离无关**。
- **例子**：1500 字节分组、100 Mbps →  
  `d_trans = (1500×8) / 100×10⁶ ≈ 0.12 ms`
- **一句话**：**把包「送上路」的时间；包越大 / 带宽越小越慢**。

> **收费站类比**：传输时延 = 收费站放行整队车要多久；升级带宽主要降这一项。

---

### 4）传播时延 Propagation Delay

- **定义**：**1 个比特**在物理介质上从链路一端到另一端的时间。
- **公式**：**d_prop = d / s**（**d**=链路长度 m，**s**=传播速率 m/s）
  - 光纤/铜缆：**s ≈ 2×10⁸ m/s**（约真空光速 2/3）
  - 卫星链路：单程约 **270 ms** 量级（往返 RTT 更大）
- **特点**：与**距离、介质**有关；**与带宽、分组长度无关**。
- **例子**：成都→北京约 1500 km →  
  `d_prop ≈ 1.5×10⁶ / 2×10⁸ = 7.5 ms`
- **一句话**：**光/电信号跑距离的时间；越远越慢，带宽救不了它**。

---

### 总时延公式（必考）

**D = 处理 + 排队 + 传输 + 传播**

多跳端到端（忽略排队/处理时）：常近似 **N × (L/R) + 总传播时延**（见 1.3）。

---

## 二、丢包 Packet Loss

- **直接原因**：路由器**缓冲区（队列）满**，新分组无处存放 → **丢弃**。
- **本质**：**流量强度 I ≥ 1**（或长期 I→1）→ 队列溢出 → 丢包。
- **后果**：TCP **重传** → 时延变大、有效**吞吐量下降**（后续运输层详述）。
- **一句话**：**路由器「堵车爆仓」，包被扔掉**。

---

## 三、吞吐量 Throughput

- **定义**：端到端**单位时间内成功送达**的数据量（bps / Mbps）。
- **核心定律（木桶效应）**：

  **吞吐量 ≈ min{R₁, R₂, …, Rₙ}**（路径上**瓶颈链路**带宽）

- **例子**：路径 100 Mbps → **10 Mbps** → 100 Mbps → 吞吐量 = **10 Mbps**。
- **带宽 vs 吞吐量**：

  | | 带宽 Bandwidth | 吞吐量 Throughput |
  |--|----------------|-------------------|
  | 含义 | 链路**理论最大**速率 | **实际**测到的端到端速率 |
  | 类比 | 路有多宽 | 实际车流量 |
  | 关系 | 上限 | ≤ 瓶颈带宽；拥塞/丢包时更低 |

- **一句话**：**网速上限由最慢那段决定；瓶颈 = 短板**（常见瓶颈在**接入网**）。

---

## 四、考试必背三句话

1. **总时延 = 处理 + 排队 + 传输 + 传播；排队时延是卡顿主因。**
2. **丢包 = 缓冲区满 = 流量太强（I≥1 或 I→1）。**
3. **吞吐量 = 瓶颈链路带宽（木桶效应），不是各段相加或平均。**

## 五、易错点（直接背）

| 易混 | 纠正 |
|------|------|
| 传输 vs 传播 | **传输**：L/R，跟**带宽、包长**有关，**跟距离无关** |
| | **传播**：d/s，跟**距离、介质**有关，**跟带宽无关** |
| 带宽 ↑ 能减传播时延？ | **不能**；主要减**传输时延**，传播受光速限制 |
| 排队时延 | **最不稳定**；拥塞时往往最大 |
| 吞吐量怎么算？ | **永远取路径最小带宽**，不是平均/总和 |
| 传输时延 vs 传播时延 | 前者「推整包上链路」；后者「bit 在介质里飞」 |
| RTT | 往返 ≈ 去程+回程各段时延之和（常含排队波动） |

---

## 六、速算口诀

- **传输**：`L/R` — 包大、路窄 → 慢  
- **传播**：`d/s` — 路远 → 慢（s≈2×10⁸）  
- **拥塞**：`La/R` — 越接近 1 越堵  
- **吞吐**：`min(各段 R)` — 看最窄那段  

---

## 个人总结（直接背）

**网络卡顿、变慢，绝大多数来自排队时延和瓶颈链路吞吐量不足；丢包是队列满了；算时延分清传输（L/R）和传播（d/s），算吞吐看木桶最短板。**
