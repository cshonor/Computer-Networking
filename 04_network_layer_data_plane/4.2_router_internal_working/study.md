# 4.2 路由器内部工作原理

> 章级精读：[§4.2 四大件](../study.md#ch4-2) · [输入口与 MAC](../study.md#ch4-input-port-mac) · **交换结构**：[三种精读](#ch4-2-switching) · [查表与 CPU](#ch4-2-switch-control) · **队列丢包**：[缓冲/AQM](#ch4-2-queue) · [速记卡](#ch4-2-queue-exam)

## 一、路由器核心硬件组成

1. **输入端口**：物理层、数据链路层、**查转发表（FIB）**
2. **交换结构（Switching Fabric）**：内部高速转发，连接输入与输出端口
3. **输出端口**：分组缓存、调度、发送到链路
4. **路由处理器**：运行路由协议、计算路由、生成路由表（**控制平面**，非每包转发路径）

## 二、路由器完整转发流程（数据平面）

1. 端口接收链路帧 → 解封装拿到 IP 分组
2. 提取目的 IP 地址
3. 查询**转发表**（最长前缀匹配 **LPM**）→ 精编：[§4.3 LPM](../4.3_ipv4_ipv6_nat/study.md#ch4-3-lpm)
4. 通过交换结构转发到对应输出端口
5. 输出端口排队、调度、重新封装发送

→ [逐跳转发全流程](../study.md#ch4-packet-walkthrough)

### 1）内存交换（Shared Memory Switching · 必考）

**定义**：整机用**一块共享内存**作转发中心，**所有端口**连到该内存，**CPU 集中控制**转发（**非 ASIC 线速**路径）。

#### 工作原理（标准流程）

1. **入端口收包** → 帧/IP 包写入**共享内存**
2. **CPU 集中处理** → 读包、查路由/转发表、决定出端口
3. **复制到出端口缓存** → 等待发送

特点：**全程 CPU 参与、无 ASIC 硬件转发、两次内存拷贝**（入→内存、内存→出）。

| 步 | 动作 |
|----|------|
| 1 | 入端口收包，**中断**通知 CPU |
| 2 | 整包**拷贝**到全局共享内存 |
| 3 | CPU 读首部，查 FIB，定出端口 |
| 4 | 从共享内存**拷贝**到输出端口缓存并发出 |

#### 核心特征（考试/面试必背）

| 特征 | 说明 |
|------|------|
| **集中式控制** | 转发决策全由 CPU；无分布式线卡 |
| **单共享缓存** | **所有端口转发共用一块共享 RAM**（端口可有**小容量**入/出队缓存，但交换中枢仍是单内存） |
| **带宽瓶颈** | 交换速率 **≤ 内存带宽 / 2**（一读一写） |
| **HOL 阻塞** | 队头包阻塞时，后续包无法转发 |
| **低速低成本** | 适合 **≤500Mbps** 量级低端设备 |

#### 典型设备

- 低端交换机：**Cisco Catalyst 8500**
- 早期路由器：**Bay Networks Accelar 1200**
- 软件路由器 / PC-based 路由器

#### vs ASIC 线速转发

| | Shared Memory | ASIC Switching |
|--|---------------|----------------|
| 控制 | **CPU** 软件转发 | **硬件芯片** |
| 时延 | 大（两次拷贝 + 查表） | 小 |
| 带宽 | 低，受内存/CPU 限制 | 高，**线速** |
| 场景 | 低端、早期 | 中高端、核心 |

**一句话**：**Shared Memory = 单内存 + CPU 集中转发 + 非线速 + 低端设备。**

<a id="ch4-2-switch-memory-concurrency"></a>

#### 高并发与瓶颈（核心结论）

**没错**：共享内存模式下**所有端口共用同一块 RAM** 作转发中枢；并发暴涨时，这块内存（及 CPU、读写带宽）会成为**硬瓶颈**，无法无上限承接海量报文。

**数据流转**

1. 各端口收到的 HTTP/上网报文 → **统一写入**共享 RAM  
2. CPU **依次**读包、查 FIB、定出端口  
3. 从 RAM **拷贝**到对应输出端口缓存 → 发出  

**高并发时四类问题**

| 问题 | 表现 |
|------|------|
| **内存容量** | RAM 固定；涌入过多 → 写不进 → **丢包** → 卡顿、超时 |
| **读写带宽** | 入写+读出 = **两次拷贝**；速率有顶 → 端口排队积压 |
| **HOL 阻塞** | 队头包卡住 → 后续正常包也被堵 → 效率骤降 |
| **CPU 算力** | 路由/转发全靠 CPU；海量并发 → 任务堆积、时延飙升 |

**设备侧应对**

| 手段 | 说明 |
|------|------|
| **端口队列缓存** | 各端口**小缓存**暂存，缓释瞬时突发；满则**新包丢弃** |
| **排队调度** | CPU 按序/优先级处理内存中报文，高并发下**串行等候** |
| **限流与丢包** | 超能力流量主动丢包；TCP **重传** → 体感变慢、时延升高 |
| **换架构** | 极限场景换 **总线 / Crossbar** 中高端设备，摆脱单内存束缚 |

**场景：局域网批量上网**

内网几十上百台同时打开网页 → 报文瞬间涌入：

- **初期**：依次写内存，CPU 正常转发，基本顺畅  
- **拉高**：内存空间、读写带宽、CPU 逐步触顶  
- **峰值**：端口缓存堆满、新报文丢弃 → 部分设备打不开页、整体卡顿  

→ 三种结构对比：[#ch4-2-switch-compare](#ch4-2-switch-compare)

<a id="ch4-2-switch-os-confusion"></a>

> **易混**：OS **IPC 共享内存**（进程通信）≠ **swap**（换页到磁盘）≠ **本节网络设备共享内存交换**。

### 2）总线交换（Bus Switching · 共享总线）

![通过总线：I₁→总线→O₂，同一时刻仅一对端口](../assets/switching_via_bus.png)

**一句话**：所有端口接在**一根公共总线**上，大家**抢这条「共用大马路」**传数据。

#### 结构

- 内部只有**一条公共高速总线**（一根数据通道）
- 所有**输入/输出端口**都挂在这根总线上
- **不靠**共享内存中转、**不靠**整块内存拷贝转发

#### 工作过程

1. 某端口收到数据包  
2. **抢占总线**使用权（仲裁）  
3. 抢到后把包**发到公共总线**上  
4. 各端口监听总线，**仅目标输出端口**收下  
5. 传完**释放总线**，下一端口再用  

#### 最核心特点

**同一时刻，总线只能被一个端口占用** → 同一时间**只能传一组数据**；别的端口只能**排队等**。

#### vs 共享内存（易混）

| | 共享内存 | 总线交换 |
|--|----------|----------|
| 共用啥 | **一块内存仓库** | **一条公路总线** |
| 怎么走 | 先入内存，CPU 分拣再出 | **抢路直传**，不经整块内存 |
| 瓶颈 | 内存读写速度（≈ **M/2**） | **总线整条带宽** |

#### 优缺点

| ✅ 优点 | ❌ 缺点 |
|---------|---------|
| 结构简单、造价便宜 | **并发极差**，不能多组同时传 |
| 端口扩展方便 | 流量大 → 排队、时延高 |
| 比内存交换通常更快 | 总线带宽 = **整机上限** |
| | 同样有 **HOL 阻塞** |

**适用**：早年**中低端交换机**、家用老路由器；现网多被 **Crossbar** 取代（教材常举 **≤32 Gbps** 量级）。

**口诀**：**一根总线大家连，抢路排队挨个传，同一时间只一车，流量一多就拥堵。**

→ 三者一页对比：[#ch4-2-switch-compare](#ch4-2-switch-compare)

### 3）纵横矩阵交换（Crossbar / 交叉开关）

![通过互连网络：I₁ 经交叉点闭合到 O₂，可多对并行](../assets/switching_via_crossbar.png)

**一句话**：**N×N 交叉开关阵列** — **行 = 输入端口**，**列 = 输出端口**，行列交点 = 可控通断开关；查表后**闭合对应交叉点**，数据**直连**转发。

#### 基础结构

- **N 个输入 × N 个输出** → **N 行 N 列**交叉开关阵列  
- 交点 **(i, j)** = 输入 i 与输出 j 之间的**可控开关（crosspoint）**

<a id="ch4-2-crossbar-matrix"></a>

#### 通路建立（五步拆解）

| 步 | 动作 |
|----|------|
| **1. 定出端口** | 入端口收包 → 解析目的 MAC/IP → 查 **FIB/路由表** → 得到**目标输出端口号**（例：入 2 → 出 5） |
| **2. 定位交点** | 行 = 输入号，列 = 输出号 → 交点 **(2, 5)** |
| **3. 闭合开关** | 调度控制器闭合 **(2,5)** → 入 2 与出 5 间形成**专属物理通路**，数据沿通路直传 |
| **4. 并行多路** | **行列不冲突**时可同时闭合多组交点（见下例） |
| **5. 释放** | 转发完毕 → 断开该交点 → 行列恢复空闲 |

**4×4 并行示例**（同一时刻）：

- **(1,3)**：入 1 → 出 3  
- **(2,1)**：入 2 → 出 1  
- **(4,2)**：入 4 → 出 2  

三组**同步转发**，互不抢道。

#### 关键规则（必背）

| 规则 | 含义 |
|------|------|
| **同行唯一** | 一个输入端口同一时刻**只能**连**一个**输出（一份数据不能同时发往多口） |
| **同列唯一** | 一个输出端口同一时刻**只能**收**一个**输入（防冲突错乱） |
| **冲突调度** | 多输入争同一输出 → 调度器**排队**（如 **iSLIP**），依次分配交点 |

#### vs 内存 / 总线（查表之后怎么走）

| 结构 | 查表后 |
|------|--------|
| **共享内存** | 拷贝到**内存仓库**，CPU 中转分发 |
| **总线交换** | **抢占公共总线**发送 |
| **Crossbar** | 锁定 **(行,列)** 交点，**闭合开关直连** |

#### 特点与适用

| ✅ | ❌ |
|----|-----|
| **多对并行**、高吞吐低时延，可达 **Tbps** | 结构复杂、成本高 |
| 高端核心/数据中心**主流**（2000 年后） | 输出争用仍要调度；非「绝对无阻塞」 |

→ 章级读图：[§4.2 Crossbar](../study.md#ch4-2-crossbar) · 三者对比：[#ch4-2-switch-compare](#ch4-2-switch-compare)

### 4）三种结构的共性：查表与控制单元（必考）

**核心结论**：三种交换结构在**寻址查表**环节都需要**控制单元**参与；MAC 校验、查 FIB/转发表、定出端口**都少不了**。差别在于 **CPU 参与程度**与**硬件分担比例**。

#### 统一前置流程（收到帧后）

| 步 | 动作 |
|----|------|
| 1 | **链路层校验**：MAC 帧 FCS 等，判数据是否完整 |
| 2 | **解析头部**：提取源/目的 MAC（及上层目的 IP 等） |
| 3 | **查转发表**：匹配目的地址 → **确定输出端口** |
| 4 | 按**各自交换架构**完成转发（内存 / 总线 / Crossbar） |

#### CPU 参与度对比

| 结构 | CPU 角色 | 查表后 |
|------|----------|--------|
| **共享内存** | **高度依赖** | 校验、查表、定口、拷贝调度**全由 CPU**；软件转发，易成瓶颈 |
| **总线交换** | **仍需 CPU 管控** | 查表、定口、**总线仲裁/占用权**由 CPU 下发；再抢总线传输 |
| **Crossbar** | **CPU 管、硬件跑** | CPU/主控：地址学习、FIB 维护、异常；定口后**指令给交换芯片** → **ASIC 闭合交点**、并行传数据，**数据面不占 CPU** |

**一句话概括**

- **共享内存、总线**：**CPU 说了算，全程主导转发**
- **Crossbar**：**CPU 定方向，硬件跑数据**

**补充**

1. 低端老设备多**纯 CPU 软件**；中高端 Crossbar 把**查表/转发下沉 ASIC**，CPU 管调度与协议  
2. **不存在**跳过 MAC 校验、端口判定**直接传**的情况  
3. 现代高端：输入口常配 **TCAM/ASIC 线速查 FIB**（见章级 [#ch4-2](../study.md#ch4-2)），与 Crossbar 硬件转发配合

### 5）三种交换结构 — 一眼分清 + 对比表

| 结构 | 通俗比喻 | 共用啥 | 瓶颈 |
|------|----------|--------|------|
| **共享内存** | **仓库** | 一块 RAM | 内存读写、CPU |
| **共享总线** | **大马路** | 一条总线 | 总线带宽 |
| **Crossbar** | **矩阵多车道** | 交叉点网格 | 调度 |

| 结构 | 路径 | 瓶颈 | 并行 | 线速 | HOL | 场景 |
|------|------|------|------|------|-----|------|
| **共享内存** | 入→**内存**→CPU→出；**两次拷贝** | **内存/2**、**CPU** | 否 | **否** | **易** | 低端 ≤500Mbps |
| **共享总线** | 入→**总线**→出 | **总线带宽** | 一对 | 中 | 有 | 企业中端 |
| **Crossbar** | 入→**交叉点**→出 | 调度 | **多对并行** | **是** | 架构级缓解 | 核心/骨干 |

| 对比项 | 内存 | 总线 | Crossbar |
|--------|------|------|----------|
| **CPU 参与** | **全程主导**（查表+拷贝+调度） | **管控+仲裁** | **定方向**；**数据面 ASIC** |
| 控制 | **CPU 集中** | CPU + 仲裁 | 硬件交叉开关 |
| 拷贝 | **2 次** | 少 | 通常无整块拷内存 |
| 带宽直觉 | **≤ M/2** | = 总线带宽 | 随端口扩展 |
| 典型 | Catalyst 8500 | ≤32Gbps 级交换机 | 核心路由器 |

## 四、缓冲区与队列丢包（考试必背）

### 1）基本概念

| 概念 | 说明 |
|------|------|
| **缓冲区（Buffer）** | 路由器/交换机**输出端口**的**队列缓存**，暂存待转发分组 |
| **队列丢包** | **输入速率 > 输出转发速率** → 队列塞满 → **后续包被丢弃** |
| **核心原因** | **拥塞（Congestion）** → 队列溢出 → 丢包 |

![队列已满：Full software queue](../assets/queue_full_software.png)

<a id="ch4-2-tail-drop"></a>

### 2）尾部丢弃（Tail Drop，默认机制）

**定义**：队列满时，**所有新到数据包直接丢弃**（队尾丢弃），直到腾出空间。

![Tail drop：新包进满队列则被丢弃](../assets/tail_drop_full_queue.png)

| | 说明 |
|--|------|
| ✅ | 最简单、**默认**、开销低 |
| ❌ | **无差别丢弃**（不区分优先级） |
| ❌ | **TCP 全局同步**：多流同时丢包 → 同时降窗/慢启动 → 带宽**忽闲忽忙** |
| ❌ | **TCP 饿死**：UDP 占带宽，TCP 长期发不出去 |

一句话：**队列满，新来丢；简单粗暴，全局同步。**

---

<a id="ch4-2-aqm"></a>

### 3）主动队列管理（AQM）：RED / WRED

**核心思想**：**队列满之前先随机丢包**（提前预警），减轻全局同步，兼顾公平与优先级。

#### （1）RED（Random Early Detection）

监控**平均队列长度 avg_len**（对实际队列长度**平滑**，非瞬时快照），设**双门限**：

| 区间 | 行为 |
|------|------|
| avg < **min_th（低门限）** | **不丢** |
| min ≤ avg ≤ **max_th（高门限）** | **按概率随机丢**（队列越长，概率越高，上限为**最大丢弃概率**） |
| avg > max_th | **全部丢弃**（等同尾部丢弃） |

![RED 丢弃概率曲线：低门限前不丢，中间斜升，高门限后全丢](../assets/red_drop_probability_curve.png)

<a id="ch4-2-red-diagram"></a>

**读图（丢弃概率曲线）**

| 阶段 | 横轴（队列长度） | 纵轴（丢弃概率） |
|------|------------------|------------------|
| ① | < **低门限** | **0** |
| ② | 低～**高门限** | **线性上升**随机丢 |
| ③ | > **高门限** | **100%**（新包全丢） |

- 横轴常用 **avg_len**，避免瞬时抖动误触发  
- 目的：**提前、随机**丢包 → 多 TCP 流**错开**降窗，减轻**全局同步**；链路利用率更平稳

**作用**：不同 TCP 流随机丢 → **避免全局同步**；提前降速 → 延迟更稳。

#### （2）WRED（Weighted RED）

- **RED + QoS**：按 **IP Precedence / DSCP** 为不同优先级设**独立**低/高门限与丢弃概率  
- 高优先级（语音/视频）**晚丢、少丢**；低优先级（下载）**早丢、多丢**

![WRED：不同 IPP 不同丢弃曲线，高优先级晚丢](../assets/wred_drop_probability_by_priority.png)

<a id="ch4-2-wred-diagram"></a>

**读图（按优先级加权）**

| 优先级（例） | 低门限 | 高门限 | 含义 |
|--------------|--------|--------|------|
| **IPP=0**（低） | 较早（如 20） | 如 40 | **先开始**随机丢 |
| **IPP=2**（高） | 较晚（如 35） | 如 40 | **更晚**才丢，保护关键流 |
| 共同 | — | **高门限**处 | 丢弃概率达**最大丢弃概率**（图中例 30%） |

| | RED | WRED |
|--|-----|------|
| 优先级 | 无 | **有** |
| 配置 | 较简 | 较复杂（queue-profile / CBQ 等） |

<a id="ch4-2-wfq"></a>

### 4）队列调度：WFQ（加权公平队列）

![WFQ：分类 → 多权重队列 → 调度 → 出接口](../assets/wfq_classification_scheduling.png)

<a id="ch4-2-wfq-diagram"></a>

**读图（输出端口流水线）**

```text
待发送包 → Classification（分类）→ Queue 1…N（各带 weight）→ Scheduling → Interface 发出
```

| 阶段 | 作用 |
|------|------|
| **Classification** | 按 IP/TOS/ACL 等把包送入**不同队列** |
| **Queue 1…N + weight** | 权重越大，**分得带宽越多** |
| **Scheduling** | 按权重**公平轮询**取包（防单流垄断） |
| **Interface** | 串行发到链路 |

| 项 | 说明 |
|----|------|
| **定位** | **拥塞管理（排队顺序）**；常与 RED/WRED（**丢包策略**）配合 |
| **原理** | 按**流**分队列；按**权重**分带宽；短包优先、防垄断 |
| **作用** | 公平性；关键流高权重**优先转发**；与 WRED 双重保护关键业务 |

<a id="ch4-2-queue-compare"></a>

### 5）对比总结（考试高频）

| 机制 | 类型 | 核心逻辑 | 优点 | 缺点 |
|------|------|----------|------|------|
| **Tail Drop** | 被动丢包 | 满了再丢，无差别 | 简单、低开销 | 全局同步、无优先级 |
| **RED** | AQM | 提前随机丢，双门限 | 防同步、延迟稳 | 无优先级 |
| **WRED** | AQM+QoS | 按优先级加权丢 | 同步+优先级 | 配置复杂 |
| **WFQ** | **调度** | 按流+权重分带宽 | 公平、低抖动 | 开销高于 FIFO |

> **易混**：RED/WRED 管**丢不丢**；WFQ 管**谁先谁后、占多少带宽**。
