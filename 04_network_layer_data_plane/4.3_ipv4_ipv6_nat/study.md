## 二、有类编址与 CIDR（必考 · 精编）

### 一、传统：A/B/C/D/E 类（有类编址，现已淘汰）

32 位 IPv4，按**最高几位固定值**硬性分成 5 类，网络位/主机位**固定长度**。

#### 1）A 类（大型网络）

| 项 | 内容 |
|----|------|
| 首位 | **0xxxxxxx** |
| 范围 | **1.0.0.0 ~ 126.255.255.255**（0 和 127 保留） |
| 网络位 / 主机位 | **8 位** / **24 位** |
| 默认掩码 | **255.0.0.0** → **/8** |
| 可用主机 | 2²⁴−2 ≈ **1677 万** |

#### 2）B 类（中型网络）

| 项 | 内容 |
|----|------|
| 前两位 | **10xxxxxx** |
| 范围 | **128.0.0.0 ~ 191.255.255.255** |
| 网络位 / 主机位 | **16 位** / **16 位** |
| 默认掩码 | **255.255.0.0** → **/16** |
| 可用主机 | 2¹⁶−2 = **65534** |

#### 3）C 类（小型网络）

| 项 | 内容 |
|----|------|
| 前三位 | **110xxxxx** |
| 范围 | **192.0.0.0 ~ 223.255.255.255** |
| 网络位 / 主机位 | **24 位** / **8 位** |
| 默认掩码 | **255.255.255.0** → **/24** |
| 可用主机 | 2⁸−2 = **254** |

#### 4）D 类（组播，不分网络/主机）

| 项 | 内容 |
|----|------|
| 前四位 | **1110xxxx** |
| 范围 | **224.0.0.0 ~ 239.255.255.255** |
| 用途 | **多播（一对多）**，如视频会议、直播 |

#### 5）E 类（保留/实验）

| 项 | 内容 |
|----|------|
| 前四位 | **1111xxxx** |
| 范围 | **240.0.0.0 ~ 255.255.255.255** |
| 用途 | **科研、实验**，不分配给普通用户 |

#### 有类编址最大问题（为什么被淘汰）

| 问题 | 说明 |
|------|------|
| 粒度僵化 | 网络大小**只能 3 种**：/8、/16、/24 |
| 严重浪费 | 需 300 台主机只能给 B 类（65534 地址），**6 万+ 闲置** |
| 路由表爆炸 | 每个 A/B/C 网络一条路由，核心路由器扛不住（**ROAD 问题**） |

---

<a id="ch4-3-cidr"></a>

### 二、现代：CIDR 无类域间路由（1993 起，现在主流）

**Classless Inter-Domain Routing**，彻底废除 A/B/C 边界，**网络前缀长度任意（常用 8~30 位）**。

#### 1）核心思想

- 不再看「类」，只看**前缀长度**：`IP地址 / 前缀位数`
- 例：
  - `192.168.1.0/24` → 前 24 位网络，后 8 位主机（等同原 C 类规模）
  - `10.0.0.0/12` → 前 12 位网络，比 A 类（/8）小、比 B 类（/16）大

#### 2）CIDR 解决了什么

1. **不浪费地址**：按需分配 /27（30 台）、/23（510 台）等（**VLSM**）
2. **路由聚合（超网）**：把连续小网合并成一条路由

```text
192.168.0.0/24
192.168.1.0/24
→ 合成 192.168.0.0/23
```

→ 骨干路由表条目大幅减少；与 BGP 聚合见 [§5.3 BGP](../../05_network_layer_control_plane/5.3_bgp_inter_as_routing/study.md)

#### 3）一句话区别

| | 有类 A/B/C | CIDR |
|---|-----------|------|
| 前缀 | 固定 **8 / 16 / 24** 位 | **任意长度** |
| 特点 | 非黑即白，**浪费严重** | 按需划分，**节约 + 聚合** |
| 现状 | 历史/考试 | **现在主流** |

路由器查表用 **最长前缀匹配（LPM）** → [§4.4 Match+Action](../study.md#ch4-4)

### 三、速记表（考试直接用）

| 类别 | 高位特征 | 首字节范围 | 网络位 | 主机位 | 默认掩码 |
|------|----------|------------|--------|--------|----------|
| **A** | 0xxxxxxx | 1–126 | 8 | 24 | 255.0.0.0 (/8) |
| **B** | 10xxxxxx | 128–191 | 16 | 16 | 255.255.0.0 (/16) |
| **C** | 110xxxxx | 192–223 | 24 | 8 | 255.255.255.0 (/24) |
| **D** | 1110xxxx | 224–239 | — | — | 组播 |
| **E** | 1111xxxx | 240–255 | — | — | 保留 |

#### 背诵一句话

**有类固定 /8/16/24 浪费大；CIDR 前缀任意按需分，还能聚合减路由表。**

## 三、IPv4 局限性

- 地址空间枯竭
- 头部设计僵化
- 缺乏原生安全性、移动性支持

## 四、NAT 网络地址转换（必考 · 精编）

### 1）核心作用

解决 **IPv4 公网地址紧缺**：内网**私有 IP** 批量复用少量**公网 IP** 上网，并**隐藏**内网主机真实地址。

**一句话**：**私网进公网，地址做翻译；外网只见网关公网地址。**

---

### 2）本质

在边界设备上**改写 IP 报文首部**（及 NAPT 时的 **TCP/UDP 端口**），把内网私有地址映射为公网地址，并通过**状态表**维持双向映射，实现多设备共享公网 IP。

---

### 3）转换对象

| 类型 | 改写内容 |
|------|----------|
| **基本 NAT** | 只改 **IP 地址**（源/目的） |
| **NAPT / PAT**（最常用） | 同时改 **IP + 传输层端口** →「一个公网 IP 多人用」 |

> 家用路由器默认 **NAPT**；服务器对外发布常用 **静态 NAT**（见下表）。

| 类型 | 映射关系 | 典型场景 |
|------|----------|----------|
| **静态 NAT** | 私网 IP ↔ 公网 IP **一对一固定** | 内网**服务器对外发布** |
| **动态 NAT** | 从**公网 IP 池**临时分配；**不改端口** | 主机数 ≤ 池大小 |
| **NAPT / PAT** | **IP + 端口**；**多主机共用一个公网 IP** | **家用路由器默认** |

---

### 4）执行位置

**边界路由器 / 家用网关 / 防火墙**（公私网交界口）。

| 平面 | 职责 |
|------|------|
| **数据平面** | 报文路过时 **Match + Action**，**直接改写首部**并转发 |
| **控制平面** | **维护映射表**（建表、老化、策略）；数据平面**查表快转** |

→ 与 [§4.4 Match+Action](../study.md#ch4-4) 一致；**不是应用层**转换。

---

### 5）状态：NAT 映射表（会话表）

| 项 | 说明 |
|----|------|
| **表项** | **内网五元组 ↔ 公网五元组**（源 IP:端口, 目的 IP:端口, 协议） |
| **出站** | 私网 → 公网，记录转换关系，改写**源** IP/端口 |
| **入站** | 公网 → 私网，**查表**还原内网地址，改写**目的** IP/端口 |
| **老化** | 带**超时**；不活跃连接自动释放表项 |

| 本质速记 | |
|----------|--|
| 转换对象 | IP（NAPT 还改端口） |
| 执行位置 | 边界网关，**数据平面改写** |
| 状态 | **映射表** 双向绑定 |

---

### 6）优点与缺点

| 优点 | 缺点 |
|------|------|
| 极大节约稀缺 **IPv4 公网地址** | **破坏端到端直连**（最大考点） |
| 隐藏内网网段与主机 IP，提升基础安全 | **P2P、IPsec、VPN**、部分穿透协议兼容性差 |
| 简化外网访问内网**边界**部署 | **映射表/端口**维护开销；可能增加时延 |

---

<a id="ch4-3-nat-flow"></a>

### 7）NAPT 工作过程（必背）

NAT 路由器维护 **NAT 转换表（映射表）**。无表项时**创建映射**；有表项时**查表改写**。

#### ① 内网主机访问外网（出站 · SNAT）

```text
内网主机 → NAT 路由器 → 互联网
```

| 步骤 | 动作 |
|------|------|
| 1 | 主机发报文：**源 = 私网 IP:端口**，目的 = 外网服务器 |
| 2 | 报文到达 NAT：**查表**；无匹配项则**新建映射**（分配公网侧端口） |
| 3 | **改写出站首部**：源 IP → **路由器公网 IP**；源端口 → **映射端口** |
| 4 | 转发到互联网；外网服务器**只看到公网 IP:映射端口** |

#### ② 外网响应返回（入站 · 反向查表）

| 步骤 | 动作 |
|------|------|
| 1 | 外网回包：**目的 = 公网 IP:映射端口** |
| 2 | NAT **查映射表**，还原内网 **私网 IP:原端口** |
| 3 | **改写入站首部**：目的 IP/端口改回内网值 |
| 4 | 转发给对应内网主机 |

> **默认**：由内向外发起的会话易建立；**外网主动连内网**需 **端口映射 / DMZ / 静态 NAT**。

<a id="ch4-3-nat-packet"></a>

### 8）报文转换示例（NAPT）

内网 `192.168.1.100:5000` 访问 `203.0.113.50:80`，路由器公网 `203.0.113.1`，分配映射端口 `62001`。

| 方向 | 改写前（关键字段） | 改写后（关键字段） |
|------|-------------------|-------------------|
| **出站** | 源 `192.168.1.100:5000` → 目的 `203.0.113.50:80` | 源 **`203.0.113.1:62001`** → 目的不变 |
| **入站** | 源 `203.0.113.50:80` → 目的 `203.0.113.1:62001` | 目的改回 **`192.168.1.100:5000`** |

**NAT 表项（逻辑）**

| 内网（私） | 公网（路由器对外） |
|------------|-------------------|
| `192.168.1.100:5000` | `203.0.113.1:62001` |

- **静态 NAT**：无端口池；私网 `10.0.0.5` **永久**对应公网 `203.0.113.10`，进出都只改 IP（端口通常不变）。  
- **校验和**：IP/端口 变化后，路由器需**重算 IP 首部校验和**（及可能影响 TCP/UDP 校验）。

→ P2P 穿透、STUN/TURN：[tcpip ch07 §7.4](../../tcpip_vol1_ed2_notes/03_network_layer/ch07_firewall_nat.md#ch07-4)

### 9）考试背诵极简版

#### 背诵一句话

**NAT：边界改 IP（NAPT 还改端口），映射表记五元组双向绑定；控制平面管表，数据平面快转；私网复用公网 IP，破坏端到端。**

#### 四句口诀

```text
本质：私网IP翻成公网IP上网
家用：NAPT/PAT，一公网IP+端口区分
服务器发布：静态NAT一对一
最大痛点：破坏端到端通信
```

#### 30 字

**NAT 缓解 IPv4 枯竭；家用 NAPT 共一公网 IP 靠端口映射；破坏端到端，碍 P2P/VPN。**

#### 考点速记

| 点 | 一句 |
|----|------|
| 家用上网 | **NAPT（PAT）** |
| 服务器外网发布 | **静态 NAT** |
| 本质 | **私有 IP → 公网 IP**（+ 端口）转换 |
| 最大痛点 | **破坏端到端通信** |
| 出站/入站 | 出站改**源**；入站按表改**目的** |

#### 易错点

| 易混 | 纠正 |
|------|------|
| NAT = 只改 IP？ | **NAPT 还改端口**；多主机才能共用一个公网 IP |
| 动态 NAT = NAPT？ | **动态 NAT** 是公网 **IP 池**轮换；**NAPT** 是 **IP+端口** 复用 |
| NAT 在应用层？ | **网络层边界设备**改写 **IP/TCP/UDP 首部** |
| IPv6 还要 NAT？ | v6 地址充足，**一般不需要**；过渡用 **NAT64** 等（见下文） |
| 外网能随便连内网？ | **否**；需映射表项或**端口转发/静态 NAT** |

## 五、IPv6 核心升级

1. 128 位地址，海量地址空间
2. 简化头部，转发效率更高
3. 原生支持 IPsec、自动地址配置、更好的移动性
4. 不再需要 NAT
