# 3.8 MTU 和路径 MTU (PMTU)

> 章级精读：[../study.md#ch03-8](../study.md#ch03-8) · 以太网帧与 MTU：[3.2 §二](./3.2-ethernet-ieee802-encapsulation.md#ch03-2-frame) · ICMP：[ch08](../../chapter08-icmpv4-icmpv6/study.md) · TCP MSS：[ch13](../../chapter13-tcp-connection-manage/study.md) · UDP 分片：[ch10](../../chapter10-udp-ip-fragment/study.md)

## 本节核心目标

掌握 **MTU**、**PMTU**、**PMTUD**、**DF 位**与 **TCP MSS** 的关系；理解为何**分片是性能杀手**及 **ICMP 黑洞**。

---

<a id="ch03-8-mtu"></a>

## 一、MTU（最大传输单元）

**MTU = 链路层一帧能装下的最大 IP 包大小（字节）**（指 **IP 层载荷上限**，不是整帧含以太网头）。

### 1）典型值

| 链路 | MTU（常见） |
|------|-------------|
| **以太网 / Wi‑Fi** | **1500**（最常见） |
| 回环 lo | 常 **65535**（逻辑，仅本机）→ [3.7](./3.7-loopback-interface.md#ch03-7-plain) |
| PPP / 隧道 | 常更小（如 1476、1400）→ [3.9](./3.9-tunnel-basics.md) |

**1500 里装什么（以太网举例）**

```text
┌──────── IP 包 ≤ 1500 ────────┐
│ IP 头(20) + TCP 头(20) + 数据  │  ← MTU 管这层
└────────────────────────────────┘
  不含：以太网帧头(14) + FCS(4)   ← 链路层额外开销
```

### 2）MTU 过大 → 分片或丢包

你发 **IP 包 > 当前链路 MTU**（如 2000 B），路由器出口只有 1500：

| IP 首部 **DF 位** | 路由器行为 |
|-------------------|------------|
| **DF = 0**（允许分片） | **切成多片**分别转发 → **IP 分片**（性能差、易丢一片全废、易乱序） |
| **DF = 1**（禁止分片） | **直接丢弃**，并回 **ICMP：Fragmentation Needed**（Type 3 Code 4），**带上该跳 MTU** |

> **结论**：**分片 = 性能杀手** → 尽量在发送端就控制包长（PMTUD + MSS）。

---

<a id="ch03-8-pmtu"></a>

## 二、路径 MTU（PMTU）

**PMTU = 从源到目的整条路径上，所有链路 MTU 的最小值**（瓶颈决定上限）。

**例子**

```text
电脑 ──1500──► 路由器 ──1400──► VPN ──1500──► 服务器
                              ↑
                         PMTU = 1400（最窄的一段）
```

---

<a id="ch03-8-pmtud"></a>

## 三、PMTUD（路径 MTU 发现）

**目的**：探测 **PMTU**，让发送方**一开始就用不超过 PMTU 的包**，避免中途被路由器分片。

### IPv4 工作步骤

```text
发包(DF=1, 按本地 MTU 1500)
    │
    ▼
路径上 MTU 够吗？ ──是──► 稳定 PMTU，正常传
    │
    否（丢包）
    ▼
路由器/设备：丢弃 + ICMP「需要分片」(带该跳 MTU)
    ▼
发送方收到 ICMP → 下调 PMTU → 重发(仍 DF=1)
    ▼
重复直到不再触发 ICMP → 得到路径 PMTU
```

| 步 | 说明 |
|----|------|
| 1 | 发送方设 **DF=1**，按本地 MTU（如 1500）发包 |
| 2 | 某跳更小 → **丢包 + ICMP Fragmentation Needed**（含 MTU） |
| 3 | 发送方 **降低 PMTU**，重试 |
| 4 | 直到包能通 → **稳定 PMTU** |

### IPv6

- 路由器**绝不**对 IPv6 做分片（除源端）→ **强制依赖 PMTUD**
- 过大包 → **ICMPv6 Packet Too Big**

### 关键坑：防火墙拦 ICMP

| 现象 | 原因 |
|------|------|
| **能建 TCP 连接，传不动数据** | SYN 小包过；数据大包被丢；**ICMP 被墙拦** → 发送方不知道要降 PMTU |
| 俗称 | **PMTU 黑洞 / ICMP 黑洞** |

**排障**：临时允许 ICMP Type 3 Code 4 / v6 PTB；或手动调小接口 MTU / MSS。

<a id="ch03-8-mss"></a>

## 四、和 TCP MSS 的关系

| 概念 | 含义 |
|------|------|
| **MTU** | 链路层一帧能承载的 **IP 包最大长度** |
| **MSS** | TCP **单次**能发的最大**数据**字节数 ≈ **MTU − IP 头 − TCP 头** |

**以太网常见**

```text
MSS = 1500 − 20(IP) − 20(TCP) = 1460 字节
```

- **PMTUD** 得到 PMTU 后，TCP 会把 MSS 设为 **PMTU − 40**（IPv4 典型头长）→ **在端上分段，不走 IP 分片**
- **TCP 分段**（按 MSS）在**主机**做；**IP 分片**在**路由器**做 — 前者好，后者差

→ UDP 无 MSS，大包只能依赖 IP 分片或应用自己切片 → [ch10](../../chapter10-udp-ip-fragment/study.md)

---

## 五、易混对照

| 易混 | 纠正 |
|------|------|
| MTU vs MSS | **MTU** 管 IP 包；**MSS** 管 TCP **纯数据** |
| 分片在哪做 | **IP 分片** = 路由器；**TCP 分段** = 本机按 MSS |
| PMTU vs MTU | **MTU** = 单跳；**PMTU** = 整条路径最小 MTU |
| DF=0 | 允许中途 **IP 分片** |
| DF=1 | 禁止分片；配合 **PMTUD** |

---

## 六、一句话笔记（可直接背）

- **MTU**：链路一帧最大 **IP 载荷**，以太网 **1500**。  
- **大包 + DF=0**：路由器 **分片**（性能差）。  
- **大包 + DF=1**：路由器 **丢包 + ICMP**。  
- **PMTUD**：发 **DF=1** 包，靠 ICMP 探路 → 得到 **PMTU**，全程避免分片。  
- **风险**：ICMP 被防火墙拦 → **黑洞**。  
- **MSS = PMTU − 40**（典型），TCP 在源头控大小。

1. 以太网 MTU 1500，TCP MSS 大约多少？  
2. DF=1 时路由器遇到超大包怎么办？  
3. PMTU 黑洞现象与原因？  
4. IPv6 为何更依赖 PMTUD？

<details>
<summary>参考答案</summary>

1. **1460**（1500−20−20，头长可变时按实际减）。  
2. **丢弃**，发 **ICMP Fragmentation Needed**（若未被拦）。  
3. 大包被丢但 **ICMP 不到发送方**，PMTU 无法下调，连接「假活」。  
4. 中间设备**不对 IPv6 分片**，必须源端或 PMTUD 控制长度。
