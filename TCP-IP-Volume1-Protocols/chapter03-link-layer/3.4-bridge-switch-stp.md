## 零、核心笔记总览（大白话 · 可直接抄）

### 1）交换机怎么知道 MAC？（MAC 地址表）

交换机**自己学**，不是手配表。

1. 帧头自带**源 MAC**  
2. 交换机：这个 MAC 从**这个端口**进来  
3. 记录 **`MAC ↔ 端口`** → **MAC 地址表**  
4. 以后再找该 MAC → **查表单端口转发**

> **听谁从哪个口来，就记下来。**

### 2）802 系列都是啥？（一句话地图）

> **IEEE 802** = 局域网标准大集合 · **802.3** = 以太网本身 · **802.1** = 交换机侧控制（VLAN、优先级、聚合…）

| 标准 | 干什么 | 详读 |
|------|--------|------|
| **802.3** | 以太网帧、速率、CSMA/CD、全双工 | [3.2](./3.2-ethernet-ieee802-encapsulation.md) |
| **802.1Q** | **VLAN 标签**（4 B），**隔离广播域** | [3.2 TCI](./3.2-ethernet-ieee802-encapsulation.md#ch03-2-vlan-tci) |
| **802.1p** | **3 bit 优先级 0–7**，QoS；**嵌在 802.1Q 标签里** | 同上 TCI 的 **PCP** |
| **802.1AX** | **链路聚合 LACP**，多线捆一条，带宽+冗余 | [3.2 §三](./3.2-ethernet-ieee802-encapsulation.md#ch03-2-advanced) |
| **802.3x** | **PAUSE 帧**，二层逐跳流控 | [3.3](./3.3-full-duplex-autoneg.md#ch03-3-pause) |

- **802.1Q**：帧里插标签，划**虚拟局域网**  
- **802.1p**：给流量打分（语音高、普通低），**不是单独一头**，在 Q 的 Tag 里  
- **802.1AX**：几根网线**捆成一根粗的**，断一根还能用  

### 3）全双工 vs 冲突域（复习）

- **Hub 半双工**：大家抢**一条总线** → **全网一大冲突域** → CSMA/CD 监听**整网**  
- **Switch 全双工**：每端口**发线 + 收线**分开 → 端口 1 与 2 **永不冲突** → 域缩到**单端口小盒子**；仅**同主机在端口内乱发**才可能端口内干扰 → [§1.1](#ch03-4-collision-plain)

### 4）端口双向 + 泛洪铁律（复习）

- 端口**可进可出**，入/出由**当前帧**决定 → [§1.2](#ch03-4-port-bidir)  
- 泛洪：**本帧**不向**本帧入端口**回发 → [§1.3](#ch03-4-flood-plain)

### 考试四行总结

1. **MAC 学习**：源 MAC + 入端口 → 自动生成 **MAC–端口表**。  
2. **全双工**：冲突域 → **单端口**；端口间无冲突；**CSMA/CD 失效**。  
3. **802**：**Q**=VLAN 广播域 · **p**=优先级在 Tag 内 · **AX**=LACP 聚合 · **3x**=PAUSE。  
4. **端口双向**；**本帧**泛洪**不回本帧入端口**。

## 一、交换机工作原理（考试标准版）

### 1）学习（Learning）

→ 大白话：[§零.1](#ch03-4-core-summary)

- 每收到一帧：提取 **源 MAC + 入端口**
- 写入/更新 **MAC 地址表**（**MAC ↔ 端口** 映射）

### 2）转发 / 过滤（Forwarding / Filtering）

查 **目的 MAC**：

| 目的类型 | 行为 |
|----------|------|
| **已知单播** | 仅从**对应唯一端口**转发 |
| **未知单播** | **泛洪**（**本帧**除入端口外所有口）→ [§1.3](#ch03-4-flood-plain) |
| **广播、组播** | **泛洪**（**本帧**除入端口外所有口） |

→ 端口双向：[§1.2](#ch03-4-port-bidir)

### 3）隔离冲突域

- **每个端口 = 独立冲突域**
- **全双工**下基本**无冲突**，**不用 CSMA/CD** → 大白话：[§1.1](#ch03-4-collision-plain) · [3.2](./3.2-ethernet-ieee802-encapsulation.md#ch03-2-mac-evolution)

### 4）广播域

- 默认：**所有端口同一广播域**
- 划分：**VLAN（802.1Q）** 隔离广播域 → [3.2 VLAN](./3.2-ethernet-ieee802-encapsulation.md#ch03-2-vlan-tci)

> **一句话**：**查 MAC 表精准转发，隔离冲突域，VLAN 隔离广播域。**

### 简答题标准答案（可直接抄）

1. **学习**：收帧记 **源 MAC–入端口**，维护 **MAC 地址表**。  
2. **转发**：查目的 MAC — **已知单播** → **单端口转发**；**未知单播/广播/组播** → **泛洪**（不含入端口）。  
3. **冲突域**：**每端口独立**；全双工**无 CSMA/CD**。  
4. **广播域**：默认**同一广播域**；**802.1Q VLAN** 划分隔离。  
5. 总结：交换机 = **L2 按 MAC 转发**；**拆冲突域、VLAN 拆广播域**。

<a id="ch03-4-collision-plain"></a>

### 1.1 大白话：为什么冲突域变成「每个端口」？

#### 以前：集线器 Hub（半双工）

- 所有电脑**共享一条总线**，**抢一条路**说话  
- 两人同时发 → **全网冲突**  
- 必须 **CSMA/CD 监听整网** → **整个网络 = 一个大冲突域**

#### 现在：交换机 + 全双工

每个端口是**物理分开的一对线**：

```text
  主机 ──发线──▶ 交换机端口
  主机 ◀──收线──  交换机端口
```

- **发、收两条线分开**，互不抢信道  
- A 走**端口 1**、B 走**端口 2** → **A、B 之间不会冲突**（不同线、不同端口）

**为什么冲突只在「端口内部」？**

- 只有**同一台主机**在自己端口的**发/收线对上**同时乱发，才可能在**该端口内部**产生信号问题  
- **端口 1 与端口 2**：线路**完全独立** → **永远不会互相冲突**  
- **冲突域** = 每个端口一个**独立小盒子**；不再是整网一个大域

**结论**：冲突从「**整网/整条通道**」→「**单端口内部**」；**CSMA/CD 失效**。

---

<a id="ch03-4-port-bidir"></a>

### 1.2 大白话：端口是「双向」的（输入/输出看当前这一帧）

> **核心**：**对！入端口完全可以变成出端口。**  
> 端口**不固定**叫输入或输出——**这一帧从哪进、从哪出，才决定谁是入/出**。

**例子：端口 1、端口 2**

| 时刻 | 发生的事 | 端口 1 | 端口 2 |
|------|----------|--------|--------|
| A → B | A 发帧给 B | **输入**（帧从 1 进） | **输出**（从 2 发出） |
| B → A | B 回复 A | **输出**（从 1 发出） | **输入**（帧从 2 进） |

**所以**：端口 1 **一会儿输入、一会儿输出**；MAC 表记的是 **`MAC ↔ 端口`**，不管上一帧是进还是出，**要发给该 MAC 时，这个口就是输出**。

> **终极一句**：端口**双向**；**仅对当前这一帧**，不向**本帧的入端口**泛洪/回发。

---

<a id="ch03-4-flood-plain"></a>

### 1.3 大白话：泛洪发给谁？（补牢）

> **考试铁律**：**这一帧**从哪个口进来，**这一帧**绝不从该口再发出去；发给**其余所有口**。

- 每一帧**只有一个入端口**（本帧的 ingress）  
- **不存在**同一帧多个入端口

**和「双向」不矛盾**

- 帧从**端口 1 进** → 泛洪时**不发回 1**（刚进来再发回无意义，还可能环路）  
- **不代表端口 1 永远不能输出**——**下一帧**完全可以从端口 1 **输出**给别的口

**例子**：交换机 **端口 1、2、3、4**

```text
情况 A — 已知单播
  帧从 端口1 进，目的 MAC 在 端口3
  → 只转发到 端口3

情况 B — 未知单播 / 广播 / 组播（泛洪）
  帧从 端口1 进
  → 发给：端口2、端口3、端口4
  → 绝不发回 端口1
```

| 你的疑问 | 答案 |
|----------|------|
| 入端口几个？ | **每帧只有 1 个**（从哪进就是哪） |
| 泛洪发给谁？ | **除入端口外所有其他口** |
| 会发回进来的口吗？ | **绝对不会** |

**三句背诵**

1. **全双工**：每端口收发分离 → 冲突域 → **单端口**；端口间不冲突。  
2. **端口双向**：入/出看**当前帧**；MAC 表记 **MAC↔端口**。  
3. **泛洪**：**本帧**从某口进 → **本帧**不发回该口；**下一帧**可从该口出。

## 二、STP / RSTP 生成树（考试极简背诵版）

<a id="ch03-4-loop-hazards"></a>

### 1）物理环路的 3 个危害（同一拓扑例子）

**拓扑**：**S1 ↔ S2** 用**两根网线**互联（冗余），形成**物理环路**；电脑 **A** 接在 S1，发**广播帧**（如 ARP）。

```text
        [A]──S1══链路1══S2
              ╲        ╱
               ╲链路2╱
                ╲    ╱
                 S1─S2  （环路）
```

#### 危害 1：帧无限泛洪（无限转圈）

1. A 发广播 → 到 **S1**  
2. S1 经**链路 1** → **S2**  
3. S2 经**链路 2** → 又回 **S1**  
4. S1 再发 S2、S2 再发 S1……  
→ **同一帧在两台交换机之间永远转圈**，无限复制、无限转发

#### 危害 2：广播风暴（网络卡死）

- 广播帧本来就要**泛洪所有端口**  
- 环路里**每转一圈复制一遍** → 包越来越多  
→ **带宽占满、CPU 爆满**，局域网瘫痪，大家都上不了网

#### 危害 3：MAC 地址表震荡

1. S1 先学到：**A 的 MAC 在端口 1**  
2. 环路转一圈，A 的帧又从**另一根线**进来  
3. S1 又记：**A 在端口 2**  
→ **一会儿端口 1、一会儿端口 2**，表疯狂刷新 → **转发出错、交换机混乱**

### 2）STP / RSTP 干什么？（大白话）

> **STP/RSTP = 逻辑上堵掉环路里多余的一条线，把环变成树，防上面 3 种灾难。**

#### STP（802.1D 传统生成树）

- **作用**：**逻辑阻塞**冗余端口；网线可能还在，但** blocked 口不转发数据**  
- 环形网 → **树型无环拓扑**  
- **缺点**：收敛慢，故障切换常 **30–50 秒**

**核心思路**：选举**根桥**，**阻塞冗余端口**，逻辑上**无环树型拓扑**。

**选举四步（必背）**

| 步骤 | 内容 |
|------|------|
| 1 **根桥** | **Bridge ID**（**优先级 + MAC**）**最小**者为根；**优先级数字越小越优先** |
| 2 **根端口 RP** | 每个**非根桥**选到根路径**开销最小**的端口 |
| 3 **指定端口 DP** | 每条网段选**离根最近**的交换机上的端口负责转发 |
| 4 **阻塞端口 BP** | **其余端口阻塞**，不转发，**消除环路** |

| 术语 | 说明 |
|------|------|
| **BPDU** | 交换机之间交换 STP 拓扑信息的**配置报文** |

**缺点**：收敛慢，常见 **30–50 秒**，链路故障切换卡顿。

### 3）RSTP（802.1w 快速生成树）

| 项 | 说明 |
|----|------|
| 兼容 | 与 STP **兼容** |
| 收敛 | **约 1–2 秒**（远快于 STP） |
| 端口角色 | 根端口、指定端口、**替代端口**、**备份端口**（更细） |
| 机制 | 减少依赖计时器，**握手协商**快速切换端口状态 |

### 4）一句话对比

- **STP**：堵冗余口 → **无环树** → **慢收敛（30–50 s）**  
- **RSTP**：同样防环 → **快收敛（1–2 s）**，几乎不断网

<a id="ch03-4-stp-exam"></a>

### 简答题标准答案（可直接抄）

1. **环路危害**（举 S1–S2 双链路例）：① 帧在交换机间**无限转圈** ② **广播风暴**占满带宽/CPU ③ **MAC 表震荡**（A 的 MAC 在端口 1/2 来回变）。  
2. **STP 目的**：逻辑**阻塞冗余端口**，形成**无环生成树**。  
3. **四步**：根桥（最小 Bridge ID）→ 根端口 RP → 指定端口 DP → **阻塞端口 BP**。  
4. **STP 缺点**：收敛 **30–50 s**。  
5. **RSTP**：802.1w，**1–2 s** 收敛，握手快速切状态。  
6. **BPDU**：交换机间传递 STP/RSTP 信息。

## 三、交换机 L2 vs 路由器 L3（边界精准版）

### 1）交换机 = 二层（L2，数据链路层）

- 只看 **MAC 地址**
- 管**同一局域网内部**（同一广播域 / 常同一 VLAN 内）
- 例：公司**一个部门**、一个 VLAN 里电脑互访

### 2）路由器 = 三层（L3，网络层）

- 看 **IP 地址**（会改 **TTL** 等）
- 管**不同网段、不同 VLAN、内网与外网**
- 例：
  - 部门 A（**VLAN 10**）↔ 部门 B（**VLAN 20**）
  - 公司内网 ↔ **互联网**
  - 大型园区、不同 **AS** 之间

### 3）必背区分

| | **交换机 L2** | **路由器 L3** |
|---|----------------|---------------|
| 寻址 | **MAC** | **IP** |
| 范围 | **局域网内部** | **跨网段 / 外网 / 不同 AS** |
| 广播域 | 默认**不分割**（靠 VLAN） | **分割**广播域 |
| 大型内网 | 同 VLAN 内互访 | **不同 VLAN 互通也要三层设备**（路由器或**三层交换机**） |

> **交换机管局域网内部；路由器管跨网段、跨外网；大内网 VLAN 互通靠路由器/三层交换机。**

→ [ch01 易混](../chapter01-overview/study.md) · 自顶向下：[§6.4](../../top_down/06_link_layer_and_lan/6.4_ethernet_arp_switch_vlan/study.md)

### 极简笔记（环路 + STP + L2/L3）

1. **环路危害**：无限泛洪 · 广播风暴 · MAC 震荡  
2. **STP/RSTP**：逻辑阻塞冗余口 → 无环树；STP 慢、RSTP 快  
3. **L2 vs L3**：交换机 MAC/局域网内；路由器 IP/跨网段外网

9. STP 与 RSTP 在收敛时间上的主要区别？

<summary>答案</summary>

1. **泛洪**到除入端口外的**所有端口**（未知单播）。
