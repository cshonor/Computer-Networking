## 零、零基础大白话导读（从零串一遍）

> 下文：**单播、组播、广播**（不用「主播」）。CSMA/CA、RTS/CTS、隐藏终端见 [§二～五](#ch03-5-cd-vs-ca)；帧地址细节见 [§六](#ch03-5-frame-mac)。

### 1）先认角色（纠正 + 通俗定义）

| 名词 | 大白话 |
|------|--------|
| **STA（站点）** | 连 Wi‑Fi 的终端：手机、电脑、平板 |
| **AP（接入点）** | 无线路由器的 **Wi‑Fi 天线 / 无线部分**；负责收发无线信号，STA 连的就是它 |
| **DS（分发系统）** | **不是一根线**，而是 AP **背后的整套有线通路**（路由器内部交换 + 网线 + 往下接的光猫等）→ 记：**AP 往下接的「有线主干路」** |

**一句话对照**

- **AP** = **无线入口**（Wi‑Fi 这边）  
- **DS** = **有线出口**（接外网、接其他有线设备的那一侧）  
- 你说的「DS 连接 Wi‑Fi（AP）和后端线路」**完全成立**。

#### 家里链路（场景拆分）

```text
手机(STA) ↔ 无线 ↔ AP(路由器无线部分) ↔ DS(内部有线+网线) ↔ 光猫 ↔ 互联网
```

| 方向 | 发生了什么 | 帧标记 |
|------|------------|--------|
| 手机发数据给 AP，要上网 | 数据**要走进 DS** | **To DS = 1**（To = **去往**，去往 DS） |
| 外网经光猫→DS→AP，再发到手机 | 数据**从 DS 出来**给手机 | **From DS = 1**（From = **来自**，来自 DS） |

**To DS / From DS**：两个二进制位，标这帧在 **无线侧** 与 **有线 DS 侧** 之间怎么穿 AP（详见 [§3](#ch03-5-beginner-tods)）。

---

### 2）为什么 Wi‑Fi 最多 4 个 MAC，网线只有 2 个？

> **联动 DS**：数据要在「无线 AP」和「有线 DS」之间来回走，就有**两层收发对象**——① 当下无线端直接收发（手机↔AP）② 最终在 DS/外网里的真正目标 → 所以需要多组 MAC（A1～A4）区分。

**有线（网线直连）**：A 直接发给 B，中间无转发 → 只需 **源 MAC + 目的 MAC**（2 个）。

**无线（必经 AP）**：存在两层关系：

1. **当下这一跳**：谁直接发、谁直接收（手机 ↔ AP）
2. **最终目标**：业务真正要去哪（外网服务器 / 另一台手机）

一层地址不够 → 802.11 用 **A1～A4 最多 4 个 MAC**。

| 字段 | 常记 | 含义 |
|------|------|------|
| **A1** | **RA** | **直接接收方**（这帧当下发给谁） |
| **A2** | **TA** | **直接发送方**（这帧当下谁发的） |
| **A3** | — | **最终源/最终目的** 或 AP 相关地址（看场景） |
| **A4** | — | 仅 **AP↔AP 桥接/WDS** 时用；家用几乎不用 |

家用手机连路由器：**一般只用 A1、A2、A3**。

<a id="ch03-5-beginner-tods"></a>

### 3）什么时候走 DS？To DS / From DS 怎么变？

先分两类通信（**局域网内互访** vs **出 Wi‑Fi 去外网/有线**）：

| 类型 | 例子 |
|------|------|
| **无线局域网内部** | 同一 WiFi 下手机互传文件、投屏 |
| **跨到外网 / 有线侧** | 刷网页、微信；访问接网线的台式机 |

| 标记 | 含义 |
|------|------|
| **To DS = 1** | 数据**要进入 / 去往 DS**（To = **去往**） |
| **From DS = 1** | 数据**从 DS 出来**（From = **来自**） |

两个位 = 给设备「报信」：**这条帧要不要进 AP 背后的有线主干（DS）**。

---

#### 场景 A：同 WiFi 内互传 → 口语「不走外网那条 DS」

例：手机 A、手机 B 都连家里**同一个**路由器 WiFi，互传文件。

```text
手机A → 无线 → AP → 无线 → 手机B
```

**人话**：在 WiFi 圈子里打转，**不用出路由器接光猫/外网的那条有线主干道**。

| 项 | 内容 |
|----|------|
| 标志位（教材简化） | **`To DS=0`，`From DS=0`** — 不「往 DS 送」、也「不是从 DS 来」 |
| MAC（3 个） | A1=**手机 B**；A2=**手机 A**；A3=**BSSID**（当前 WiFi/AP 标识） |

> **802.11 术语提醒**：标准里 **DS 不单指一根网线**，AP 内部转发也算分发。infra 模式下 A→B **抓包常见两跳**：A→AP 常为 **To DS=1**；AP→B 常为 **From DS=1**。口语「不走 DS」多指**不上外网、不出有线 WAN 口**；**0/0** 更典型是 **IBSS 设备直连**。以抓包为准 → [§六](#ch03-5-frame-mac)。

---

#### 场景 B：访问外网 / 家里有线设备 → **必须走 DS**

例：手机刷视频；访问**网线插路由器**的台式机。

**（1）上行：手机发出去** — `To DS=1`，`From DS=0`

```text
手机 → 无线 → AP → 进入 DS（内部有线+网线）→ 光猫/外网/有线电脑
```

| 地址 | 填谁 |
|------|------|
| A1 | **AP** |
| A2 | **手机** |
| A3 | 最终目的（外网/有线侧） |

**（2）下行：数据回手机** — `To DS=0`，`From DS=1`

```text
外网/有线电脑 → 从 DS 出 → AP → 无线 → 手机
```

| 地址 | 填谁 |
|------|------|
| A1 | **手机** |
| A2 | **AP** |
| A3 | 最终来源 |

---

#### 场景 C：AP ↔ AP 无线桥接（双路由扩展 WiFi）

数据既要进本机 DS、又要从对端 DS 来 → **`To DS=1`，`From DS=1`**，**必须用 A4**（家用极少）。

---

#### 极简对照表（背这张）

| 通信场景 | To DS | From DS | 是否走 DS（口语） |
|----------|-------|---------|-------------------|
| 同 WiFi 内互传（无线内网） | 0 | 0 | ❌ 不出有线主干/外网（简化） |
| 手机**上传**到外网/有线 | 1 | 0 | ✅ **进入** DS |
| **下载**到手机 | 0 | 1 | ✅ **来自** DS |
| 路由器↔路由器桥接 | 1 | 1 | ✅ 跨 DS（+ **A4**） |

**IBSS（无 AP，手机直连手机）**：`To DS=0`，`From DS=0`，与「同 WiFi 互传简化」类似。

---

#### 核心逻辑（回答「为啥有时走、有时不走」）

1. **不走 DS（口语）**：双方都在**无线圈子里**，AP 主要做无线转发，**不必动用接光猫/外网的那条有线主干道**。  
2. **走 DS**：目标在**有线网或互联网**，必须经过 AP **背后的有线主干（DS）**。  
3. **To DS / From DS** = 告诉对端：**这帧要不要进、要不要出那条有线主干**。

→ 地址字段详表：[§六](#ch03-5-frame-mac)

### 4）CSMA/CA、隐藏终端、RTS/CTS（核心机制）

**为何不用有线的 CSMA/CD？**

- 有线：一根线同时只能一家发，能**边发边听**冲突 → **CSMA/CD**。
- 无线：自己发射时会**盖住周围信号**，**听不到别人是否在发** → 不能可靠「边发边检测」→ 改用 **CSMA/CA（冲突避免）**：**先发前协商、提前避让**，而不是撞了再停。

**隐藏终端（hidden node）**

```text
  手机A ····· AP ····· 手机B
  A、B 互相听不见，但都能听见 AP
```

- A 听信道空 → 发；B 也听信道空 → 发 → **两路信号在 AP 处撞车**。
- **互相看不见、却在 AP 撞车**的站 = **隐藏终端**。

**RTS/CTS（专门缓解隐藏终端）**

| 缩写 | 含义 |
|------|------|
| **RTS** | Request To Send —「我要占信道一段时间」 |
| **CTS** | Clear To Send — AP 回复「可以发，大家别抢」 |

流程：**RTS → CTS → 数据 → ACK**。周围站（含隐藏终端）**都能听到 AP 的 CTS** → 按 **NAV** 静默 → 避免在 AP 处撞车。

人话：**RTS/CTS = 先打招呼占坑**，再传大包。→ 时序详图：[§五](#ch03-5-rts-cts-timeline)

---

### 5）从头到尾串一遍

1. **STA** 上网必经 **AP**；AP 背后有线网 = **DS**，用 **To DS / From DS** 标流向。  
2. 因有「直接跳」与「最终目标」，帧里最多 **4 个 MAC**（家用常用 3 个）。  
3. 无线有**隐藏终端**，不能用 **CSMA/CD**。  
4. 用 **CSMA/CA + 可选 RTS/CTS** 提前避冲突。

### 6）极简背诵版

1. **AP** = 无线入口；**DS** = AP 背后整套有线主干（不是一根线）。  
2. **同 WiFi 互传**（简化）**0/0**；**上传 1/0**；**下载 0/1**；**AP 桥接 1/1 + A4**。  
3. **有线 2 MAC**；**Wi‑Fi 最多 4 MAC**（无线一跳 + 最终目标）。  
4. **隐藏终端** → **CSMA/CA + RTS/CTS** 提前防冲突。

<a id="ch03-5-csma-ca"></a>

## 一、教材那句话怎么理解？

> **CSMA/CA（冲突避免）**  
> 无线电难以像网线那样可靠检测冲突 → 用**退避**与可选 **RTS/CTS** 缓解**隐藏终端**。

| 拆开 | 大白话 |
|------|--------|
| **CSMA/CA** | **载波监听多路访问 / 冲突避免**；**Wi‑Fi（802.11）** 用这个 |
| **CSMA/CD** | **冲突检测**；**有线以太网（Hub 半双工时代）** 用这个 |
| 为何无线难检测冲突 | 发的时候**听不到别人**、信号强弱差大 → **不能可靠「边发边听」** → 只能 **尽量避免（CA）** |
| 退避 | 信道空后**随机等一会儿**再发，减少同时抢信道 |
| RTS/CTS | **可选**短帧预约，专门帮**隐藏终端** |

<a id="ch03-5-cd-vs-ca"></a>

## 二、CSMA/CA 怎么干活？和 CSMA/CD 有啥区别？

### 1）CSMA/CA 流程（通俗）

1. 想发 → **先听**无线信道：有没有人在说话？  
2. **忙** → 一直等到空闲。  
3. **空闲** → **不马上发**，再抽一个**随机时间（退避）**再发（大家号码不同，少撞车）。  
4. 时间到、信道仍空 → **发数据**。  
5. 对方回 **ACK**；**没收到 ACK** → 认为丢包/冲突 → **退避窗口加大**，再随机重传。

### 2）一句话对比

| | **CSMA/CD（有线）** | **CSMA/CA（无线）** |
|---|---------------------|---------------------|
| 策略 | **边发边听**，冲突了**立刻停、发干扰、后退重传** | **不检测冲突**，靠**监听 + 随机退避 + ACK** **避免**冲突 |
| 典型场景 | Hub **半双工**共享网线 | **802.11 Wi‑Fi** |

### 3）无线为什么不能用 CSMA/CD？

| 原因 | 说明 |
|------|------|
| **收发共用天线** | **正在发的时候，收不到别人的信号**（自己信号太强）→ **近端掩蔽** |
| 信号衰减大 | 远处冲突信号很弱，**很难判断是不是碰撞** |
| 结论 | 做不到网线那种**可靠冲突检测** → 只能改成 **CA（避免）** |

→ 有线 Hub/半双工详解：[3.2](./3.2-ethernet-ieee802-encapsulation.md#ch03-2-mac-evolution) · 交换机全双工后 CSMA/CD 消失：[3.3](./3.3-full-duplex-autoneg.md) · [3.4](./3.4-bridge-switch-stp.md#ch03-4-collision-plain)

<a id="ch03-5-backoff"></a>

## 三、退避是什么？（二进制指数退避）

> **排队类比**：信道空后，**不是大家一起往前冲**，而是每人**随机抽一个号**，按号排队；号小的先发。

- 从 **0～退避窗口** 里**随机选一个数**，倒计时结束再检查信道。  
- **没收到 ACK**（认为冲突/丢包）→ 窗口**翻倍**，再随机选 → 冲突越多，等得越久、越「谨慎」。  
- 教材常叫 **二进制指数退避**（与 [study.md §3.5](../study.md#ch03-5) 中 DIFS/SIFS 配合使用）。

<a id="ch03-5-hidden-node"></a>

## 四、隐藏终端（hidden node）— 重点例子

### 场景：A、B（AP）、C

```text
    A ·········  B(AP) ········· C
    └─能听见B─┘         └─能听见B─┘
    A 和 C 互相听不见（墙/距离）
```

| 步骤 | 发生了什么 |
|------|----------------|
| 1 | **A** 要发给 **B**，听信道：**没声音**（因为**听不到 C**） |
| 2 | **C** 也要发给 **B**，听信道：**也没声音**（听不到 A） |
| 3 | **A、C 同时往 B 发** |
| 4 | 在 **B** 处两路信号**撞在一起、数据全乱**；**A、C 自己不知道** |

这就是 **隐藏终端**：**互相听不见，却同时打向同一个 AP**；只靠「先听 + 随机退避」**解决不了**（因为根本听不到对方）。

<a id="ch03-5-rts-cts"></a>

## 五、RTS/CTS 完整时序（A → AP，C 为隐藏终端）

**整体顺序**：**RTS → CTS → 数据帧 → ACK**

| 角色 | 说明 |
|------|------|
| **A** | 发送端 |
| **B(AP)** | 接入点 / 接收端 |
| **C** | **隐藏终端**（能收到 B，**收不到 A**） |

| 缩写 | 全称 | 作用 |
|------|------|------|
| **RTS** | Request To Send | 「我要占用信道传数据，请批准」 |
| **CTS** | Clear To Send | 「批准；**这段时间所有人别占信道**」 |

<a id="ch03-5-rts-cts-timeline"></a>

### 步骤 1：A 发 **RTS**

- A 听信道空闲 → 发短帧 **RTS** 给 B。  
- **传播**： mainly **A ↔ B**；**C 收不到 RTS**，此时 **C 不知情**。

### 步骤 2：B 回 **CTS**（广播静音）

- B 收到 RTS → 立刻 **CTS**，帧里带**信道占用时长（NAV）**。  
- **传播**：**B 覆盖内所有站（含 A、C）**。  
- **C 听到 CTS** → **立刻静默**，倒计时结束前不抢信道。

### 步骤 3：A 发**正式数据**

- A 收到 CTS → 开始传**业务数据**；**C 全程静默**，不干扰。

### 步骤 4：B 回 **ACK**

- B 收齐数据 → **ACK** 告知 A 成功；**信道占用结束**，全网恢复 **CSMA/CA 竞争**。

### 时间轴简图（背诵版）

```text
时间线 →————————————————————————————————————————→

A:     [发RTS]───────[收CTS]──────[发数据]──────[收ACK]
B(AP): [收RTS]───────[发CTS]──────[收数据]──────[发ACK]
C:     (听不到RTS)──────────[收到CTS]───(静默)───(静默结束)
```

**NAV（虚拟载波监听）**：CTS 等帧里带「还要占信道多久」；即使物理听不清发射方，也按 NAV **预约、暂不发送** → [study.md §3.5](../study.md#ch03-5).

### 关键考点

| 问 | 答 |
|----|-----|
| **为何能解决隐藏终端？** | A、C **互听不见**，但都能听见 **AP 的 CTS** → C 被**强制静默** → 不会与 A 同时在 B 处撞车。 |
| **何时开 RTS/CTS？** | **可选**；**大包**开（避冲突收益大）；**小包**关（多两次握手，反而慢）。 |
| **对比有线 CSMA/CD** | 有线：**边发边听，冲突立刻停**；无线：**先预约（RTS/CTS）提前规避**，靠 **ACK** 判断成败。 |

<a id="ch03-5-summary"></a>

#### 五句话复盘（专抄）

1. **CSMA/CA**：无线用；**先听 → 空闲 → 随机退避 → 发 → ACK**；**避免**冲突，不 **检测**。  
2. **不用 CSMA/CD**：发时**听不到别人**（近端掩蔽），**没法边发边检测碰撞**。  
3. **隐藏终端**：A、C **互听不见**，却**同时向同一 AP 发** → **在 AP 处撞车**；单靠退避**不够**。  
4. **RTS/CTS**：短帧预约；**CTS 让能听见 AP 的站都静音**（如 C）；**大包常用**。  
5. **顺序**：**RTS → CTS → Data → ACK**；**CTS 发出时 C 闭嘴**。

<a id="ch03-5-frame-mac"></a>

## 六、802.11 帧：最多 4 个 MAC 地址

> 零基础逐字解释：[§零.2～3](#ch03-5-beginner)

| 对比 | 以太网 | **802.11 Wi‑Fi** |
|------|--------|------------------|
| MAC 个数 | **2**（源、目的） | 最多 **4**（A1～A4） |
| 为何更多 | 有线基本**端到端** | 无线常经 **AP 转发**，要分清**直接收发**与**最终源/目的** |

**To DS / From DS** 两位决定实际用 **3 个还是 4 个**地址（考试记场景即可）。

### 四个地址含义（A1～A4）

| 字段 | 常记名 | 含义 |
|------|--------|------|
| **A1** | **RA** | **直接接收者**（下一跳） |
| **A2** | **TA** | **直接发送者**（当前发这帧的设备） |
| **A3** | — | **BSSID**（AP 的 MAC）或**最终目的 DA**（看场景） |
| **A4** | — | 仅 **WDS / 无线中继**（AP↔AP）时用，标**原始发送者** |

> **一句**：无线是「**中间转发**」多，所以要 4 个 MAC；有线 2 个就够。

### 三种常见组合（一眼对照）

| 场景 | 用几个 | A1（RA） | A2（TA） | A3 | A4 |
|------|--------|----------|----------|-----|-----|
| **手机 → AP**（上行，To DS） | **3** | AP | 手机 | 最终目的（如服务器 MAC） | — |
| **AP → 手机**（下行，From DS） | **3** | 手机 | AP | 最终源或相关地址 | — |
| **AP ↔ AP**（WDS/桥接） | **4** | 对端 AP | 本 AP | BSSID 等 | **原始发送者** |

<a id="ch03-5-bss-assoc"></a>

## 七、BSS、SSID 与上线流程

### 1）概念分清

| 词 | 大白话 |
|----|--------|
| **SSID** | Wi‑Fi **名字**（如 `Home-WiFi`），**给人看** |
| **BSS** | 一个 AP 覆盖的**基本服务集**（一片无线网络） |
| **BSSID** | AP 的 **MAC 地址**，**给机器认**；同一 SSID 可有多个 BSSID（多 AP） |

### 2）三步上线：扫描 → 关联 → 认证

```text
扫 Beacon/Probe → 选 SSID → 关联（拿 AID）→ 认证（密码/4次握手）→ 上网
```

#### ① 扫描（找周围 Wi‑Fi）

| 方式 | 怎么做 | 特点 |
|------|--------|------|
| **被动扫描**（手机常默认） | 只听 AP 的 **Beacon**（信标，管理帧），带 SSID/BSSID/信道 | AP 约每 **100ms** 广播；**省电** |
| **主动扫描** | 手机发 **Probe Request** → AP 回 **Probe Response** | **搜得快**、**更耗电** |

#### ② 关联（注册到 AP）

手机选好 SSID → **Association Request** → AP **Association Response**，分配 **AID（站内编号）**。  
→ **已加入该 BSS**，链路层「挂上了」，**数据尚未加密**。

#### ③ 认证（安全）

| 类型 | 说明 |
|------|------|
| **802.11 开放/共享密钥** | 早期弱认证，**现基本不用** |
| **WPA / WPA2 / WPA3** | 关联后 **4 次握手**（常配合 **802.1X**），验密码、协商密钥 → **加密业务数据** → [§八 安全](#ch03-5-security) |

### 3）五句专抄（帧 + 管理）

1. Wi‑Fi 帧最多 **4 MAC**：A1(RA)、A2(TA)、A3、A4(**WDS 专用**)。  
2. **SSID=名字，BSSID=AP 的 MAC**。  
3. **扫描**：被动听 **Beacon** / 主动 **Probe**。  
4. **关联**：注册 AP，得 **AID**。  
5. **认证**：**WPA2** 等 **4 次握手**后加密上网。

## 十、简答题 / 背诵（可直接抄）

1. **CSMA/CA**：无线用；**先听 → 空闲 → 随机退避 → 发 → 等 ACK**；**不检测冲突，只避免冲突**。  
2. **为何不用 CSMA/CD**：发时**听不到别人**（近端掩蔽），**无法可靠边发边检测碰撞**。  
3. **CSMA/CD vs CA**：有线 **CD=冲突后立刻停**；无线 **CA=退避+ACK 尽量避免**。  
4. **隐藏终端**：A、C **互听不见**，却**同时向同一 AP(B) 发** → **在 AP 处冲突**。  
5. **RTS/CTS**：短帧预约；**CTS 让所有能听见 AP 的站静音**；缓解隐藏终端；**大包常用**。  
6. **退避**：随机等待 + 冲突后**指数增大窗口**，分散发送时间。  
7. **RTS→CTS→Data→ACK** 顺序；CTS 期间 **C 被静音**。  
8. 安全：**WEP 废弃** → **WPA2(AES)** → **WPA3**。  
9. **802.11 帧**：最多 **4 MAC**；手机↔AP 常 **3 个**；**WDS** 用 **A4**。  
10. **SSID / BSSID**；上线：**扫描 → 关联(AID) → 认证(4次握手)**。
