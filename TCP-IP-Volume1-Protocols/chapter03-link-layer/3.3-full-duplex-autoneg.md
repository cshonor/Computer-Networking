<a id="ch03-3-duplex"></a>

## 一、双工模式：半双工 vs 全双工

### 1）半双工（Half-duplex）

| 项 | 说明 |
|----|------|
| 行为 | 同一时刻**只能发或只能收**，不能同时进行 |
| 机制 | 依赖 **CSMA/CD** 防碰撞 |
| 场景 | **Hub**、老旧**共享式**以太网 |

### 2）全双工（Full-duplex）

| 项 | 说明 |
|----|------|
| 行为 | 收发**物理分离**，**可同时发+收** |
| 冲突 | 交换机**点对点**链路，**CSMA/CD 基本失效、冲突消失** |
| 场景 | 现代**交换机 + 网线**默认全双工；**千兆及以上**几乎只用全双工 |

## 二、自动协商（Auto-negotiation）

### 1）协商什么

两端自动匹配共同支持的：

- **速率**：10 / 100 / 1000 Mbps  
- **双工**：半双工 / 全双工  
- **流控**（可选）

**优先级（速率越高越优；同速率下全双工 > 半双工）**

```text
1000M 全双工 > 1000M 半双工 > 100M 全双工 > 100M 半双工 > 10M 全双工 > 10M 半双工
```

### 2）标准规定

| 速率 | 自动协商 |
|------|----------|
| **10/100M** | **可选**（可关） |
| **1000M（千兆）** | **强制开启**，**不能关闭** |

### 3）核心规则（考试必背）

| 情况 | 结果 |
|------|------|
| **两端都自动协商** | 通常协商到**最优**（多为**全双工**） |
| **一端强制全双工、另一端自动协商** | 自动协商端常降级为**半双工** → **双工不匹配** → **大量丢包、延迟高** |
| **光纤以太网** | **不支持**自动协商 → **必须手动**配速率/双工 |

<a id="ch03-3-cheat"></a>

## 三、10 行极简背诵版

1. **半双工**：收发不能同时；要 **CSMA/CD**；Hub 时代。  
2. **全双工**：可同时收发；交换点对点**无经典冲突**。  
3. **自动协商**：匹配 **10/100/1000M + 半/全双工 + 流控**。  
4. 优先级：**速率优先，同速率全双工 > 半双工**。  
5. **千兆**：自动协商**强制开**。  
6. 两端自协商 → 通常**全双工最优**。  
7. 一端强全双工、一端自协商 → **半双工不匹配** → **丢包**。  
8. **光纤**：**手动配置**，不自协商。  
9. 全双工交换网：**CSMA/CD 基本消失**。  
10. 一句话：**自协商配速率双工；全双工交换无冲突。**

## 四、其他（WoL / 802.3x / 802.1X）

### 省电：WoL（Wake-on-LAN）

- **魔术包**（特定以太帧）唤醒休眠主机

### 802.3x 流量控制

- 拥塞时发 **PAUSE 帧**（类型 **0x8808**），短暂停发  
- **L2 流控**，≠ TCP 拥塞控制

### 802.1X（提及）

- 端口**接入认证**（企业有线/Wi‑Fi）→ [3.5](./3.5-wireless-80211.md)

## 五、自测（4 题）

1. 全双工交换端口还需要 CSMA/CD 吗？为什么？  
2. 千兆以太网能否关闭自动协商？  
3. 一端固定全双工、另一端自动协商，常见后果？  
4. 光纤链路能否依赖自动协商？

<details>
<summary>答案</summary>

1. **基本不需要**；点对点全双工**无共享介质冲突**，CSMA/CD **失效**。  
2. **不能**；1000M **强制**自动协商。  
3. **双工不匹配**（自协商端常变半双工）→ **丢包、性能差**。  
4. **不能**；需**手动**配置。

</details>
