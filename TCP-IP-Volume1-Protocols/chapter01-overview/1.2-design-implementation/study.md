## 本节核心目标

区分协议**规范**与**实现**；掌握**分层**及**复用 / 分解 / 封装**在数据路径上的含义。

---

## 分层 (Layering)

- 将复杂通信问题拆成若干层，每层只处理**一个方面**（寻址、可靠传输、应用语义等）。
- 便于分工、替换实现（如换网卡驱动而不改 HTTP 逻辑）。
- 经典对照：**OSI 七层** vs 本书 **TCP/IP（ARPANET）四层/五层** 实用模型。

## 复用、分解与封装

| 术语 | 方向 | 含义 |
|------|------|------|
| **封装 (Encapsulation)** | 发送 | 上层 PDU 作为下层**载荷**，加本层首部（有时加尾部） |
| **复用 (Multiplexing)** | 发送 | 多个上层流汇聚到同一下层通道（靠首部字段区分） |
| **分解 (Demultiplexing)** | 接收 | 根据首部字段把 PDU **交给正确上层**协议/套接字 |

```text
应用数据
  → 加传输层首部 → TCP/UDP 段
  → 加网络层首部 → IP 数据报
  → 加链路层首部 → 以太网帧
```

接收路径：**自下而上拆包 + 首部字段查表分解**。

---

## 实现注意

- 同一 RFC 可有多种栈实现（性能、缓冲区、零拷贝策略不同）。
- 调试抓包时看到的是**各层首部 + 载荷**嵌套，不是“单层大数组”。
