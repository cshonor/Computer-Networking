<a id="ch02-4-cidr"></a>

## 一、CIDR（无类别域间路由）

**Classless Inter-Domain Routing** — **无类前缀分配，废除 A/B/C 刚性边界**

### 核心特点

| 要点 | 说明 |
|------|------|
| 无类 | 不再固定 **A(/8)、B(/16)、C(/24)** |
| 格式 | **网络前缀 + 主机位**，前缀长度**任意**（/21、/22、/30…） |
| 记法 | **`IP/前缀长度`**（如 `192.168.1.0/24`） |
| 掩码 | `/24` → `255.255.255.0`（与点分掩码等价） |

### 解决的两大问题

1. **地址枯竭**：按需分前缀，避免「只要 50 台却占一个 B 类」式浪费  
2. **ROAD**：配合**聚合**，减少核心路由器 **RIB/FIB** 表项

### 特殊前缀（常考）

| 前缀 | 用途 |
|------|------|
| **`/32`** | **主机路由**（单 IP） |
| **`/31`** | **点对点链路**（RFC 3021，2 个地址） |
| **`/0`** | **默认路由**（`0.0.0.0/0`） |

<a id="ch02-4-aggregate"></a>

## 二、路由聚合（Aggregation / Supernet）

**一句话**：**多条连续小路由 → 一条更短前缀（超网），减少表项**

### 原理

- 多个**连续、前缀高位相同**的小网段 → 合并为**一个更大网段**  
- 本质：找所有地址的**最长公共前缀（LCP）**

### 聚合条件（必考）

1. 地址块**连续**  
2. 前缀**高位相同**（从左对齐比较）  
3. 聚合后前缀**变短**（覆盖范围变大）

### 三步计算法

1. 各网段转**二进制**  
2. 从左找**连续相同的位** → 新前缀长度  
3. **网络地址** = 公共前缀 + 主机位全 0  

### 例题（必会）

聚合：`192.1.12.0/24`、`192.1.13.0/24`、`192.1.14.0/24`、`192.1.15.0/24`

```text
第三字节：
12 = 00001100
13 = 00001101
14 = 00001110
15 = 00001111
→ 前 6 位相同 → 16 + 6 = 22 位前缀
→ 结果：192.1.12.0/22
```

### 作用

- 减 **RIB/FIB** 表项，降内存/CPU  
- **BGP**：ISP 向上游常只通告**聚合路由**  
- 与 **IANA→RIR→ISP** 层级分配天然契合 → [2.6](./2.6-address-allocation.md)

### 拓扑敏感分配（易聚合 vs 难聚合）

```text
难聚合：核心表多条 /24 各指不同路由器
易聚合：核心表一条 /22 → 190.154.24.0/22 覆盖 .24–.27
```

## 三、30 秒写卷子

| 概念 | 一句话 |
|------|--------|
| **CIDR** | 无类 `IP/x`，废 A/B/C，解**地址枯竭** |
| **聚合** | 连续小前缀 → **更短一条**，解 **ROAD** |
| **关系** | CIDR 是基础；**聚合是 CIDR 的核心应用** |

**口诀**：无类按需分前缀，连续同高位可超网，前缀变短表项少。

## 四、自测（2 题）

1. 能否把 `10.1.0.0/24` 与 `10.2.0.0/24` 聚合成一条？为什么？  
2. `172.16.0.0/16` 可聚合成 `/8` 吗？（假设只有这一块）

<details>
<summary>答案</summary>

1. **不能**（一般情况）。第三字节 `1` vs `2` 高位不同，**不连续/公共前缀不够长**，不能合成一条合理超网覆盖两者且仍“连续块”。  
2. **不能聚成 /8**。`/16` 已是 `172.16.0.0/16`；要变成 `/8` 需覆盖整个 `172.0.0.0/8`，与“只有 /16 这一块”矛盾。聚合是**合并多条连续小路由**，不是随意缩短单条。

</details>
