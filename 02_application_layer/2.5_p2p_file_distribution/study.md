# 2.5 P2P 文件分发

> 章级精读：[../study.md#ch2-5](../study.md#ch2-5) · C/S vs P2P 架构：[2.1 §二](../2.1_network_application_principle/study.md#ch2-1-exam)

## 本节核心目标

理解 **P2P 去中心化分发原理**、与 **C/S 的对比优势**，以及 **BitTorrent** 工作机制。

---

## 一、P2P 基本概念（必背）

**P2P（Peer-to-Peer，对等网络）**

- **去中心化**：无「唯一中心大服务器」；**Peer 地位平等**
- 节点既是 **下载者（客户）**，也是 **上传者（服务器）**
- 用户越多 → **聚合上传能力越强** → 整体往往**越快**（**自扩展**）

一句话：**人人为我，我为人人，没有老大。**

---

## 二、P2P vs C/S（必考）

| | **C/S（传统）** | **P2P** |
|--|----------------|---------|
| 下载来源 | **只从中心服务器** | **Peer 互传**；服务器常只做**初始/元数据** |
| 用户增多 | 服务器带宽瓶颈 → **越慢、易堵** | 总上传能力↑ → **整体常更快** |
| 分发时间 | 随 N **线性变差**趋势 | **有界、可扩展**（见下公式） |
| 单点故障 | 服务器挂则全挂 | **无单点**（Tracker 除外，见 BitTorrent） |

**记忆**：**C/S 人多卡死；P2P 人多越快。**

### 教材分发时间下界（选考）

- **C/S**：`D_CS ≥ max{ F/u_s, N·F/d_min }`  
- **P2P**：`D_P2P ≥ max{ F/u_s, F/d_min, N·F/(u_s + Σu_i) }`  

`F` 文件大小；`u_s` 服务器上行；`d_min` 最慢下载链路；`N` 用户数；`Σu_i` 所有 Peer **聚合上行**。  
当 `Σu_i` 很大时，P2P 第三项可很小 → 体现**弹性**。

---

## 三、BitTorrent（经典 P2P，必考）

### 1）核心角色

| 角色 | 作用 |
|------|------|
| **Tracker** | 小服务器；**不存文件**；帮 Peer **互相发现**（Peer/Seed 列表） |
| **Seed（种子）** | **已有完整文件**，持续上传 |
| **Peer（对等方）** | 正在下，只有**部分块** |
| **Torrent（洪流）** | 同一文件的所有 Seed + Peer 集合 |

### 2）种子文件 `.torrent`

很小，**不是视频/安装包本身**，包含：

- 文件名、大小  
- **分块（Piece）信息 + 每块哈希**（校验完整性）  
- **Tracker 地址**  

### 3）工作流程（7 步）

1. 发布者把文件切成 **Piece**（常 **256KB** 量级）  
2. 生成 **`.torrent`**，挂到网站  
3. 用户下载 `.torrent`，用 BT 客户端打开  
4. 客户端连 **Tracker** → 获得 Peer/Seed **列表**  
5. **并行**向多个 Peer/Seed **拉不同块**  
6. 每下完一块 → **立刻上传**给别人（**边下边传**）  
7. 块齐 → 拼成完整文件 → 你变成 **Seed**  

### 4）两大机制（高效 + 防白嫖）

| 机制 | 作用 |
|------|------|
| **Rarest First（最稀缺优先）** | 优先下全网**最少人有的块**，防某块**绝种** |
| **Tit-for-Tat（以牙还牙）** | 谁传我多，我优先回传谁；**激励上传、抑制搭便车** |

---

## 四、P2P 优势总结

1. **去中心化、无单点故障**（文件在 Peer 间；Tracker 是轻量协调点）  
2. **高可扩展**：用户越多，聚合供给越强  
3. **服务器压力小**：大流量在 Peer 间  
4. **适合大文件、大规模分发**（镜像、游戏包、视频离线分发）

## 五、考试 / 面试速记

| 点 | 一句 |
|----|------|
| P2P | 对等、互传、**自扩展** |
| vs C/S | 人多 **C/S 慢**，**P2P 快**（理想模型） |
| Tracker | **只协调**，不存文件 |
| BT | 分块 + `.torrent` + **Rarest First** + **Tit-for-Tat** |

### 易错

| 易混 | 纠正 |
|------|------|
| `.torrent` = 完整文件？ | **否**；是**元数据**（块哈希 + Tracker） |
| P2P 完全无服务器？ | **Tracker** 仍是服务器；**文件内容**在 Peer |
| BitTorrent = 所有 P2P？ | **经典一种**；还有 IPFS 等其它模型 |

### 30 字终极版

**P2P 对等互传自扩展；BT 分块+Tracker+Rarest+Tit-for-Tat；人多越快，适大文件。**

---

## 个人总结（直接背）

**P2P 天生适合大文件大规模分发，具备极强的可扩展性。C/S 靠中心带宽；P2P 靠用户聚合上行。BitTorrent 用 Tracker 发现节点、分块并行、最稀缺优先与互惠上传。**
