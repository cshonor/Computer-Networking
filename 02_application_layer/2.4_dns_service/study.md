# 2.4 DNS 域名解析服务

> 章级精读：[../study.md#ch2-4](../study.md#ch2-4) · **RR 速记表**：[#ch2-4-rr](#ch2-4-rr) · [12 步解析](#ch2-4-flow)

## 本节核心目标

**理解域名（好记）如何转换成 IP（机器能路由）**；掌握四层架构、递归/迭代、缓存、RR 与解析全流程。

---

## 一、DNS 作用（一句话）

**DNS = 互联网通讯录**：**人类易记域名 ↔ 机器识别 IP** 双向映射。

- 例：`www.baidu.com` → `180.101.49.11`（A 记录）
- 没有 DNS，只能敲 IP，难记、难用
- 还承载 **MX、CNAME、NS** 等（不只 A 记录）

**运输层**：DNS 报文通常走 **UDP 53**（大响应/区传输等可用 TCP 53）

---

## 二、分布式层级架构（必考 · 4 层）

DNS 是**树状分布式数据库**，从上到下：

| 层级 | 谁 | 干什么 |
|------|-----|--------|
| **1. 根服务器** | 全球 **13 组**逻辑根（A–M） | **不存**具体网站 IP；只指向 **TLD 服务器** |
| **2. 顶级域 TLD** | `.com`、`.cn`、`.org`… | 指向 **二级域权威服务器** |
| **3. 权威服务器** | 域名所有者/服务商（百度、阿里云） | **真正存** 域名→IP 等 **RR** |
| **4. 本地 DNS / 递归解析器** | 路由器、运营商、8.8.8.8、114… | **替你跑腿**：查缓存 → 根 → TLD → 权威 → 回 IP |

```text
根 (.)
└── .com / .cn（TLD）
    └── example.com（权威）
        └── www.example.com → A 记录 → IP
```

---

## 三、递归 vs 迭代（必背）

| | **递归 Recursive** | **迭代 Iterative** |
|--|-------------------|-------------------|
| **谁对谁** | **客户端 → 本地 DNS** | **本地 DNS → 根 / TLD / 权威** |
| **行为** | 本地 DNS **包办到底**，直接给你**最终 IP** | 上级只答「**下一站问谁**」，自己接力查 |
| **你发几次** | 客户端通常 **1 次**（等结果） | 解析器对每层 **多次** 查询 |
| **例子** | 浏览器问 114 DNS：给我 `www.x.com` 的 IP | 根：去问 `.com`；`.com`：去问 `x.com` 权威 |

**一句话**

- **递归**：我帮你查完，**直接给答案**（客户端 ↔ 本地 DNS）  
- **迭代**：我只告诉你**下一站**（根、TLD、权威之间）

> 教材常记：**主机对本地 DNS 用递归；本地 DNS 向上游用迭代**（减轻根负载）。

---

## 四、DNS 缓存（效率关键）

为**少查根、快返回**，多级缓存：

| 层级 | 说明 |
|------|------|
| **浏览器缓存** | 最短，分钟级 |
| **OS 缓存** | 含 **hosts** 文件 + 系统 DNS 缓存 |
| **本地 DNS 缓存** | 由 **TTL** 控制，常几分钟～几小时 |
| **各级上游** | 也可缓存 RR |

- **TTL（Time To Live）**：记录可缓存多久；**过期**才重新向权威查询  
- **效果**：多数访问**命中缓存**，不必每次问到根

## 五、资源记录 RR（考试常考 · 精编完整版）

DNS 数据库的每一条条目都叫 **资源记录 RR（Resource Record）**。

### 1）标准格式（必背）

**(Name, Value, Type, TTL, Class)**

| 字段 | 含义 |
|------|------|
| **Name** | 域名（主机名） |
| **Value** | 对应值（IP / 别名域名 / 邮件服务器域名等） |
| **Type** | 记录类型（A / AAAA / CNAME / MX / NS / PTR / SOA…） |
| **TTL** | 生存时间（秒）；控制**缓存多久** |
| **Class** | 地址类，一般为 **IN（Internet）** |

考试简写常记：**Name, Value, Type, TTL**

区文件示例：`www.example.com. IN A 192.0.2.1`（`IN` = Class）

### 2）常考类型总表（直接背）

| 类型 | 全称 | 作用 | 典型例子 | 考试重点 |
|------|------|------|----------|----------|
| **A** | Address | 域名 → **IPv4** | www.baidu.com → 180.101.49.11 | 最基础、必考 |
| **AAAA** | IPv6 Address | 域名 → **IPv6** | www → 2001:db8::1 | 与 A 区别 |
| **CNAME** | Canonical Name | **别名 → 规范域名** | www → cdn.example.com | **不能**与 A 等同名共存 |
| **MX** | Mail Exchange | 邮件服务器；**数字小优先** | example.com MX **10** mail.example.com | Value 必须**域名** |
| **NS** | Name Server | 本域**权威 DNS** | example.com NS dns1.example.com | 子域委派 |
| **PTR** | Pointer | **反向：IP → 域名** | 1.1.168.192.in-addr.arpa → host | 反解、邮件反垃圾 |
| **SOA** | Start of Authority | 区域授权起始（主 DNS、序列号、刷新时间） | zone 第一条 | 结构、zone 头 |

### 3）逐条精解（带易错点）

#### ① A 记录（IPv4）

- `www.example.com. IN A 192.0.2.1`
- **易错**：同一域名可有多条 **A**（**负载均衡**）

#### ② AAAA 记录（IPv6）

- `www.example.com. IN AAAA 2001:db8::1`

#### ③ CNAME 记录（别名）

- `www.example.com. IN CNAME cdn.example.com.`
- **易错**：CNAME 所在名**不能同时**有 **A、MX、NS** 等；CNAME **不能指向 IP**

#### ④ MX 记录（邮件）

- `example.com. IN MX 10 mail.example.com.`
- **易错**：Value **必须是域名**；多 MX：10 主、20 备… → 配合 [2.3 SMTP](../2.3_email_smtp_pop3_imap/study.md)

#### ⑤ NS 记录（权威委派）

- `example.com. IN NS dns1.example.com.`

#### ⑥ PTR 记录（反向）

- IPv4：`1.2.0.192.in-addr.arpa. IN PTR www.example.com.`（IP 字节**反写** + `in-addr.arpa`）

#### ⑦ SOA 记录（区域头）

- 标识**主 DNS、管理员邮箱、序列号、刷新/重试/过期**等（zone 管理）

### 4）考试超简口诀（5 行）

1. **A 指 IPv4，AAAA 指 IPv6**  
2. **CNAME 是别名，指向域名不指 IP**  
3. **MX 管邮件，数字小的先干活**  
4. **NS 指权威，负责本域解析权**  
5. **PTR 反向查，IP 反解成域名**  

### 5）默写速记表（一页）

| 类型 | 记什么 |
|------|--------|
| **A** | 名 → **IPv4** |
| **AAAA** | 名 → **IPv6** |
| **CNAME** | 别名 → **域名**（无 A/MX/NS 同存） |
| **MX** | 邮件服；**小数字优先**；值=域名 |
| **NS** | 谁管这个域（权威） |
| **PTR** | **IP → 名** |
| **SOA** | zone 授权头 |
| **TTL** | 缓存秒数（所有 RR 都有） |

## 六、解析全过程（`www.example.com` 示例）

1. **浏览器缓存** → 命中则结束  
2. **OS 缓存 / hosts** → 命中则结束  
3. **递归查询 → 本地 DNS**（客户端只问这一步）  
4. **本地 DNS 缓存** → 命中则返回  
5. **迭代问根** → 返回「去问 **.com** TLD」  
6. **问 .com TLD** → 返回「去问 **example.com** 权威」  
7. **问权威** → 返回 **A 记录**：`www.example.com` → IP  
8. **本地 DNS** 把 IP 给浏览器，并**缓存**（按 TTL）  
9. 浏览器用 **IP** 建立 **TCP**，发 **HTTP/HTTPS**

```text
浏览器 ──递归──► 本地 DNS ──迭代──► 根 → TLD → 权威
         ◄── IP ──      ◄── 逐级指引/最终 A 记录
```

→ 之后：[2.2 HTTP/HTTPS](../../02_application_layer/2.2_http_and_web/study.md#ch2-http-tls-payload)

## 七、DNS 安全（了解）

| 威胁 | 说明 |
|------|------|
| **DNS 劫持/污染** | 篡改返回 IP，导向恶意站 |
| **缓存投毒** | 污染解析器缓存，长期生效 |
| **反射/放大攻击** | 利用 DNS 作 DDoS 放大 |

**防护思路**：**DNSSEC**（签名验证）、**DoT**（DNS over TLS）、**DoH**（DNS over HTTPS）

## 八、考试 / 面试一句话（直接背）

| 点 | 口诀 |
|----|------|
| **作用** | 域名 ↔ IP（通讯录） |
| **架构** | 根 → TLD → 权威 → **本地递归** |
| **查询** | **客户端↔本地：递归**；**本地↔上级：迭代** |
| **缓存** | **TTL**；浏览器/OS/本地 DNS |
| **RR** | 见 [#ch2-4-rr](#ch2-4-rr) 五句口诀 |

### RR 五句口诀（默写）

**A 四 AAAA 六；CNAME 别名指域名；MX 邮件小优先；NS 权威管本域；PTR 反向 IP 找名。**

### 易错

| 易混 | 纠正 |
|------|------|
| 根服务器存所有 IP？ | **否**；只指向 **TLD** |
| 全是递归？ | **否**；向上游是 **迭代** |
| CNAME 直接给 IP？ | 只能指向**域名**；该名**不能**再有 A/MX/NS |
| MX 能写 IP？ | **否**；必须**域名**，再查 A |
| MX 优先级 | **数字越小越优先** |
| 一条 A 只能一个 IP？ | **否**；可多条 A **负载均衡** |
| DNS 只用 TCP？ | 常见 **UDP 53** |

---

## 个人总结（直接背）

**DNS 是互联网通讯录，没有 DNS 只能用 IP 上网。根→TLD→权威存记录；本地 DNS 递归替客户端查完；向上迭代逐级指路；TTL 缓存提速；RR 记 A/MX/CNAME 等。**
