# 6.1 链路层服务与概述

> 章级精读：[§6.1](../study.md#ch6-1) · 逐跳原理：[#ch6-hop-ip-frame](../study.md#ch6-hop-ip-frame) · **三类服务模型**：[#ch6-1-service-models](#ch6-1-service-models) · **LAN/WAN 定义**：[1.2](../../01_network_basics/1.2_network_edge_and_access/study.md#ch1-2-lan-wan-def)

## 本节核心目标

理解**链路层只管相邻两节点这一段**；掌握**三类链路层服务模型**（以太网 / WiFi / PPP·HDLC）及与 TCP 的区别；能区分**链路层逐跳** vs **网络层端到端**。

---

<a id="ch6-1-simple"></a>

## 〇、新手易懂：链路层管哪一段？

> **网络层（IP）管端到端「从哪到哪」；链路层管每一小段「这一跳怎么送」。**

| 层次 | 管什么 | 地址 | 变不变 |
|------|--------|------|--------|
| **网络层** | 端到端路径 | **IP** | 源/目 IP **全程不变** |
| **链路层** | **相邻两节点之间**这一跳 | **MAC** | **每跳必换** |

**和「LAN → 接入网 → WAN → LAN」的关系**

- 那是**整条上网路径**的叫法（见 [1.2 标准说法](../../01_network_basics/1.2_network_edge_and_access/study.md#ch1-2-lan-wan-path)），**不是**链路层专用术语。
- 链路层不关心「电话网/WAN」这些名字，只关心：**当前这一跳**用以太网/Wi‑Fi/光纤成什么**帧**、用哪个 **MAC** 发出去。
- 路由器每过一跳：**解帧 → 查 IP 路由 → 重封新帧**（IP 不变，MAC 换）。

→ 精编：[§6.1 逐跳五步](../study.md#ch6-hop-ip-frame) · 帧≠IP：[#ch6-frame-vs-ip](../study.md#ch6-frame-vs-ip)

## 一、链路层定位

- 位于网络层之下，物理层之上
- 核心目标：**在相邻节点之间，为 IP 分组提供可靠的传输服务**
- 工作范围：单条链路内的主机/路由器之间

![链路层逐跳：路径上每段链路独立成帧，路由器内上至网络层再下封装](../assets/link_layer_position_hop_by_hop.png)

| 图上要点 | 含义 |
|----------|------|
| **LAN → 接入网 → WAN → LAN** | **端到端路径**跨多种网段（标准说法 → [1.2](../../01_network_basics/1.2_network_edge_and_access/study.md#ch1-2-lan-wan-path)）；**不是**「电话网开头」那种旧顺序 |
| 每台路由器三层栈 | **物理层**接线 → **链路层**成帧/解帧 → **网络层**查路 |
| 红箭头「上→下」 | 入：**剥链路帧**到 IP；出：**再套新链路帧**发往下一跳 |
| 与网络层区别 | 网络层管**端到端**；链路层只管**相邻两节点这一段** |

→ 展开：[§6.1 逐跳原理](../study.md#ch6-hop-ip-frame) · [第 4 章实例](../../04_network_layer_data_plane/study.md#ch4-packet-walkthrough)

**背版三句**

1. 端到端 = **IP 数据报**，源/目 IP **全程不变**  
2. 每一跳 = **解帧 → 查 IP 路由 → 重封新帧**（新 MAC，同一 IP 包）  
3. **NIC 适配器**负责帧与比特流转换  

**帧 vs IP**：[以太网帧 ≠ IP 数据报](../study.md#ch6-frame-vs-ip) — 帧是箱子、MAC+FCS 校验、类型字段可装 ARP 等

## 二、链路层核心职责

1. **成帧**：将 IP 分组封装为链路层帧（加上头部/尾部）
2. **链路接入**：通过 MAC 协议解决多主机共享同一链路的问题
3. **差错检测与纠正**：检测并修复传输错误（如 CRC 校验）
4. **可靠传输**：部分协议（如 802.11）提供确认重传机制
5. **流量控制**：防止发送方发送过快，超出接收方处理能力
6. **全双工/半双工控制**：协调链路收发方向

## 三、链路层三类服务模型（必考）

> **结论**：下面三类都是**数据链路层（二层）**提供的服务类型，**不是**网络层 / 应用层。

| # | 类型 | 代表协议 |
|---|------|----------|
| 1 | **无确认无连接** | **以太网（802.3）** |
| 2 | **有确认无连接** | **802.11（WiFi）** |
| 3 | **面向连接** | **PPP、HDLC** |

→ 全层对照：[#ch6-1-layer-compare](#ch6-1-layer-compare) · 章级：[§6.1.1 服务](../study.md#ch6-1)

<a id="ch6-1-service-models"></a>

### 1）无确认无连接：以太网（802.3）

| 项 | 说明 |
|----|------|
| **建连接** | **无**「先拨号/先握手」，直接发帧 |
| **ACK** | **无**；发出去就不管，不保证对方收到 |
| **特点** | **尽力而为、简单高效、不可靠** |

**为什么以太网这样设计**

- 局域网**误码率很低**，丢包少  
- 追求**高速、低成本**；加 ACK 会拖慢、变复杂  
- 丢包、乱序、重传交给上层 **TCP**

**一句话**：以太网 = 二层「裸奔」发包，不确认、不重传，**快就行**。

→ 以太网精读：[6.4](../6.4_ethernet_arp_switch_vlan/study.md)

---

<a id="ch6-1-wifi-ack"></a>

### 2）有确认无连接：802.11（WiFi）

| 项 | 说明 |
|----|------|
| **建连接** | **无** PPP 那种「建链→传→拆链」的完整链路流程 |
| **ACK** | **有**；单播帧发完等 **ACK**，超时**重传** |
| **特点** | 无线**误码高、干扰大**，必须确认+重传；但仍**不建立长期连接** |

**和以太网对比**

| | 以太网 | WiFi |
|---|--------|------|
| 发完 | 发了就走 | 发 → 等 ACK → 没 ACK 重传 |
| 建链 | 无 | 无（每包独立，不「拨号建链」） |

**一句话**：WiFi = **不建连接**，但**每包都要确认、重传**，保证无线链路尽量可靠。

→ MAC/CSMA-CA：[6.3](../6.3_mac_protocol/study.md)

---

<a id="ch6-1-ppp-hdlc"></a>

### 3）面向连接：PPP、HDLC

| 项 | 说明 |
|----|------|
| **流程** | **先建连接 → 传数据 → 释放连接** |
| **HDLC** | 有序号、确认、重传、滑动窗口 → **可靠传输** |
| **PPP** | 比 HDLC 简单，**不保证可靠**；但仍须 **LCP 建链路 → NCP 协商网络层** → **面向连接服务模型** |

**典型场景**

| 协议 | 场景 |
|------|------|
| **PPP** | 拨号上网、**PPPoE**、点到点专线 |
| **HDLC** | 早期 WAN、路由器间专线互联 |

**一句话**：PPP/HDLC = **打电话**：先拨号（建链）→ 通话（传数据）→ 挂机（拆链）。

---

### 4）三者对比（极简表）

| 类型 | 代表 | 建连接 | ACK | 重传 | 特点 |
|------|------|--------|-----|------|------|
| 无确认无连接 | 以太网 802.3 | ❌ | ❌ | ❌ | 尽力而为、快、不可靠 |
| 有确认无连接 | WiFi 802.11 | ❌ | ✅ | ✅ | 无线每包确认重传 |
| 面向连接 | PPP、HDLC | ✅ | ✅ | ✅ | 先建链再传，可靠/可控 |

<a id="ch6-1-layer-compare"></a>

### 5）关键理解 · 全层对照

| 易混 | 纠正 |
|------|------|
| 三类服务在哪一层？ | 全是**数据链路层（二层）**，不是 IP / 应用层 |
| 「无连接」= 不封装？ | **否**；以太网、WiFi 都封装成**帧**，只是不提前建链路、不保证可靠 |
| 「面向连接」= TCP 专利？ | **否**；二层 PPP/HDLC 也面向连接，范围是**一条链路**；TCP 是**端到端** |

**全层对照（连接 / 确认）**

```text
┌──────── 二层（本跳链路）────────────────────────────────────┐
│ 以太网：无连接、无ACK     WiFi：无连接、有ACK     PPP：面向连接 │
└──────────────────────────────────────────────────────────────┘
┌──────── 三层（网络）────────────────────────────────────────┐
│ IP：无连接、不可靠（尽力而为）                                  │
└──────────────────────────────────────────────────────────────┘
┌──────── 四层（端到端）────────────────────────────────────────┐
│ UDP：无连接、不可靠    TCP：面向连接、可靠（三次握手/ACK/重传）   │
└──────────────────────────────────────────────────────────────┘
```

| 层次 | 无连接不可靠 | 有确认/可靠 | 面向连接 |
|------|--------------|-------------|----------|
| **二层** | 以太网 | WiFi（ACK 重传） | PPP、HDLC |
| **三层** | **IP** | — | — |
| **四层** | **UDP** | — | **TCP** |

→ TCP/UDP：[第 3 章](../../03_transport_layer/study.md) · 链路 vs TCP 可靠：[§6.1.1 对比](../study.md#ch6-1)

## 四、链路层实现位置

- 通常由网卡（NIC）硬件 + 驱动实现，部分功能在软件
- 以太网、WiFi 等不同链路，对应不同的链路层协议栈

## 五、本节核心考点

- 链路层 vs 网络层 交付范围区别
- 链路层六大核心职责
- **三类服务模型**：以太网 / WiFi / PPP·HDLC（建连接？ACK？）
- 二层「面向连接」vs 四层 TCP「面向连接」的范围区别

## 六、易错点 · 锚点

| 易混 | 纠正 |
|------|------|
| 链路层 = 端到端寻路？ | **否**；端到端是 **IP/网络层**；链路层只管**本跳** |
| 「电话网→LAN→WAN」顺序？ | **LAN → 接入网 → WAN → LAN** → [1.2](../../01_network_basics/1.2_network_edge_and_access/study.md#ch1-2-lan-wan-path) |
| 帧里的 IP 每跳变？ | **MAC 每跳变**；**IP 不变** |
| 以太网 = 可靠传输？ | **尽力而为**，无 ACK；**802.11 才有 ACK 重传** |
| WiFi = 面向连接？ | **否**；**有确认无连接**（每包 ACK，不建长期链路） |
| PPP = 和 HDLC 一样可靠？ | PPP **服务模型面向连接**；**可靠程度**依实现，常弱于 HDLC |
| 三类服务是 IP/TCP？ | **全是二层**；IP 无连接；TCP 才是四层面向连接 |
