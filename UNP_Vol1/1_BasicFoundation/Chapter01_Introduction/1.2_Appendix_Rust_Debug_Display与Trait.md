# Rust 附录 · `Debug` / `Display`、Trait 与「鸭子类型」

> 与 UNP 示例相关：[daytimesrv.rs](./code/1.5_SimpleTimeServer/rewrite_rust/daytimesrv.rs) 里 `format!("{:?}", …)` · [1.2 Rust 客户端](./1.2_Appendix_Rust客户端.md)

<a id="rust-debug-display"></a>

## 结论（先说）

**Rust 不是 Python 鸭子类型。** Rust 是**静态强类型 + Trait 编译期约束**；能不能 `println!`、`format!`，取决于类型**是否实现了对应 Trait**，编译器在**编译阶段**就定死。

| 格式化 | 需要的 Trait | 常见来源 |
|--------|--------------|----------|
| **`{}`** | **`Display`** | 一般**手写** `impl Display`（业务友好格式） |
| **`{:?}`** | **`Debug`** | 常 **`#[derive(Debug)]`**（编译器自动生成 `impl Debug`） |

---

<a id="rust-struct-print"></a>

## 一、结构体默认不能随意 `println!`

```rust
struct User { name: String }
let u = User { name: "aa".into() };

// println!("{}", u);   // 编译错误：未实现 Display
// println!("{:?}", u); // 编译错误：未实现 Debug
```

加上派生：

```rust
#[derive(Debug)]
struct User { name: String }

println!("{:?}", u);  // OK：编译器帮你 impl Debug
// println!("{}", u);  // 仍错误：没有 Display
```

**`Display` 要开发者自己实现**（官方刻意分开「给人看」和「给调试看」）：

```rust
use std::fmt;

impl fmt::Display for User {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "用户名：{}", self.name)
    }
}
```

之后才能 `println!("{}", u)`。

**UNP 示例**：`SystemTime` 标准库已实现 **`Debug`**，故 [daytimesrv.rs](./code/1.5_SimpleTimeServer/rewrite_rust/daytimesrv.rs) 可写：

```rust
format!("{:?}\r\n", std::time::SystemTime::now())
```

若要类似 C `ctime` 的可读格式，应**自己 `impl Display`** 或改用 `chrono` 等库，而不是指望 `{:?}` 长得好看。

<a id="rust-trait-static"></a>

## 二、Trait = 显式绑定、编译期校验

一个类型能不能：

- 用某种 `println!` 格式；
- 作为泛型参数 `fn f<T: SomeTrait>(x: T)`；

**只看有没有 `impl SomeTrait for Type`**，**编译期**检查，不是运行时再「碰运气找方法」。

`#[derive(Debug)]` 只是**语法糖**：等于编译器自动写 `impl Debug for User { … }`，**仍是静态实现**，不是动态鸭子。

<a id="rust-vs-duck"></a>

## 三、为什么 ≠ Python 鸭子类型？

### Python：运行时动态

> 「长得像鸭子、会叫就是鸭子」——**运行时才看有没有 `.hello()`**，写代码时不强制接口。

```python
class A:
    def hello(self): pass

class B:
    def hello(self): pass

def test(x):
    x.hello()   # A、B 都能传，无静态约束
```

没 `hello` → **运行时报错**。

### Rust：静态 Trait 约束

```rust
trait Hello { fn hello(&self); }

struct A;
impl Hello for A { fn hello(&self) {} }

struct B;   // 没 impl Hello

fn test<T: Hello>(x: T) { x.hello(); }

// test(B);  // 编译失败：B 不满足 Hello
```

| | Rust | Python 鸭子 |
|---|------|-------------|
| 检查时机 | **编译期** | **运行期** |
| 约束方式 | **必须 `impl Trait`** | **碰巧有同名方法** |
| 失败表现 | **编译 error** | **AttributeError 等** |

<a id="rust-summary"></a>

## 四、精简背诵

1. **`{}` → Display（常手写）**；**`{:?}` → Debug（常 derive）**。  
2. **Rust 无鸭子类型**：Trait 静态绑定，编译校验。  
3. **`derive(Debug)` ≠ 动态**：是自动 `impl`，不加 derive 就没有 Debug。

---

<a id="rust-wasm"></a>

## 五、延伸（Wasm）

Rust 在编译 WebAssembly 前已完成 Trait 检查，打包后一般**不会出现**「运行时才找不到方法」那类 JS/Python 动态错误——与网络编程里「尽早用类型系统拦住 bug」同一思路。
