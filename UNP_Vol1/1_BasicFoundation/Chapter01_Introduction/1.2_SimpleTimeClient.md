## 一、整体流程速记

### TCP 客户端标准五步法

| # | 步骤 | API / 行为 |
|---|------|------------|
| 1 | **创建套接字** | `socket()` → 内核分配 **sockfd** |
| 2 | **填充服务端地址** | `sockaddr_in` + **网络字节序** |
| 3 | **发起连接** | `connect()` → 内核 **三次握手** |
| 4 | **循环读取** | `while (read())` → TCP **字节流** |
| 5 | **关闭** | `exit` / `close` → **FIN**，四次挥手 |

```text
socket(fd) → 组装 IP+端口(网络序) → connect(三次握手) → while recv/read → exit/close(FIN)
```

### 内核时序对照

| 应用层 | 内核 / 协议 |
|--------|-------------|
| `socket` | 创建套接字文件描述符 |
| 填 `servaddr` | 目的 IP + 端口（**htons / inet_pton**） |
| `connect` | 发起 **TCP 三次握手** |
| `read` 循环 | 从 TCP 接收缓冲区取字节流 |
| `exit`（或 `close`） | 回收 fd，发 **FIN** 断开 |

## 二、关键 API 与结构体复盘

### 1. `socket(AF_INET, SOCK_STREAM, 0)`

| 参数 | 含义 |
|------|------|
| **`AF_INET`** | **IPv4** 地址族 |
| **`SOCK_STREAM`** | 面向连接 **TCP** |
| **`0`** | 协议由前两项**自动选择**（TCP） |

| 返回值 | 说明 |
|--------|------|
| **≥ 0** | 套接字描述符 **sockfd** |
| **< 0** | 创建失败（查 `errno`） |

### 2. `sockaddr_in` 地址结构体

```c
struct sockaddr_in {
    short           sin_family;   /* AF_INET */
    in_port_t       sin_port;     /* htons(13) — 主机序 → 网络大端 */
    struct in_addr  sin_addr;     /* inet_pton("x.x.x.x") */
    char            sin_zero[8];  /* bzero 清零，与通用 sockaddr 对齐 */
};
```

| API | 作用 |
|-----|------|
| **`bzero(&servaddr, sizeof(servaddr))`** | 整块清零 — UNP 经典写法，避免 **`memset` 参数（填充值/长度）写反** |
| **`htons(13)`** | **端口**必须转**网络字节序** |
| **`inet_pton(AF_INET, "…", &sin_addr)`** | 字符串 IP → **二进制网络序**（内部完成转换） |

→ [Ch 3.2 地址结构](../Chapter03_SocketProgramIntro/3.2_SocketAddressStructure.md) · [Ch 3.4 字节序](../Chapter03_SocketProgramIntro/3.4_ByteOrderFunction.md)

## 二附、网络字节序是什么？（「组装 IP + 端口」通俗版）

> 你看到的流程 **`组装 IP + 端口（网络序）`** 指的就是：在 **`sockaddr_in servaddr`** 里填好**要去哪台机器、哪个端口**，而且**端口（以及 IP 二进制）必须按网络上规定的字节顺序存放**，再交给 `connect`，内核才能正确发 TCP 连接。

### 1. 1.2 在干什么（先对齐一句话）

| 说法 | 对不对 |
|------|--------|
| **「一个简单的时间获取客户程序」** | ✅ 对：本机当**客户端**，连对方 **TCP 13 端口（Daytime）**，把对方发来的**时间文字**读出来打印 |
| **五步法** | ✅ `socket` → **填 servaddr** → `connect` → **`while read`** → 退出/`close` |
| **「组装 IP + 端口」** | ✅ 就是往 **`servaddr`** 里写 **`sin_addr`（IP）** + **`sin_port`（端口 13）** + **`sin_family`（IPv4）** |

```text
你写的 servaddr（用户态结构体）
        │
        ▼ connect(sockfd, &servaddr, …)
内核 TCP/IP 协议栈：用里面的「目的 IP + 目的端口」去路由、发 SYN（三次握手）
        │
        ▼ 连上后
内核把收到的 TCP 字节放进该连接的接收缓冲区；你的 read() 从缓冲区取数据
```

（末尾若语音里混进无关英文可忽略；和内核无关。）

### 2. 字节序：同一个数，在内存里字节怎么排

多字节的数（例如 **2 字节的端口号 13**、**4 字节的 IPv4**）在内存里占多个字节。**先存高字节还是先存低字节**，不同 CPU 可能不同，这叫 **字节序（endian）**。

| 名称 | 通俗理解 | 常见机器 |
|------|----------|----------|
| **大端（big-endian）** | **高位字节在前**（更像人类写数字：从左到右是高位→低位） | **网络上传输用的标准** |
| **小端（little-endian）** | **低位字节在前** | 很多 **x86 / x64 PC** |

**例子：端口号 13**（十六进制 `0x0013`，占 2 字节）

| 字节序 | 内存里两个字节（地址从左到右） |
|--------|--------------------------------|
| 大端 | `00` `13` |
| 小端 | `13` `00` |

同一个数 **13**，两种排法**字节内容不同**。若你把「本机排法」的 2 字节直接交给网络协议，而对方按**大端**解读，就会把端口读成**别的数**（例如误读成 4864），连接会失败或连错服务。

### 3. 主机字节序 vs 网络字节序

| 术语 | 含义 |
|------|------|
| **主机字节序（host byte order）** | 你这台电脑上 CPU 习惯的字节排列（PC 多为**小端**） |
| **网络字节序（network byte order）** | TCP/IP 规定：**在网络上按大端**传输多字节字段 |

因此 API 约定：

- 放进 **`sockaddr_in.sin_port`** 的端口，必须是 **网络字节序**。
- 放进 **`sin_addr`** 的 IPv4 二进制，也必须是 **网络字节序**（按大端存的 32 位地址）。

你在 C 里写的 `servaddr` 最终会通过 `connect` 交给**内核**；内核不会帮你「猜」端口是不是写反了，**写错序 = 目的端口错**。

### 4. 和 1.2 三行代码的对应关系

```c
servaddr.sin_port = htons(13);
inet_pton(AF_INET, argv[1], &servaddr.sin_addr);
```

| 代码 | 你在填什么 | 为什么要转换 |
|------|------------|--------------|
| **`htons(13)`** | **端口** 13 | **h**ost **to** **n**etwork **s**hort：把本机字节序的 16 位整数转成**网络字节序**再赋给 `sin_port` |
| **`inet_pton(...)`** | **IP** 字符串 → `sin_addr` | 函数**内部**已按 IPv4 规则生成**网络序**二进制，一般**不要**再对 `sin_addr` 做 `htonl`（重复转换会错） |
| **`bzero` + `sin_family = AF_INET`** | 结构体其余字段清零、标明 IPv4 | 避免垃圾字节；族与 `socket(AF_INET,…)` 一致 |

记忆口诀（1.2 够用）：

- **端口**：你手写的整数 → 用 **`htons` / `htonsl` 族**（发送前）；从套接字读出的端口用 **`ntohs`**（收到后）。
- **IP 字符串**：用 **`inet_pton`**，别自己拆字节。
- **IP 已是 `in_addr` 且从网络来**：用 **`ntohl` 族** 再给人看（如 `inet_ntop` 前有时要理清，初学先记 pton/ntop 成对）。

→ 函数全集：[Ch 3.4 字节序函数](../Chapter03_SocketProgramIntro/3.4_ByteOrderFunction.md)

### 5. 「组装」完成后内核做什么（和字节序的关系）

| 步骤 | 谁在做 | 说明 |
|------|--------|------|
| 你填 `servaddr` | **应用程序** | 仅在进程内存里；必须已是**正确的网络序 IP/端口** |
| `connect()` | **系统调用 → 内核** | 内核读取 `servaddr` 里的**目的 IP、目的端口**，为该 `sockfd` 建立连接状态机，发 **TCP SYN**（三次握手第一步） |
| 路由选路 | **内核协议栈** | 根据目的 IP 查路由表，决定从哪块网卡出去 |
| `read()` | **内核 + 你** | 对端 Daytime 发来的时间在 TCP 载荷里；内核缓冲，你的 `read` 拷贝到 `recvline` |

**重点**：网络字节序解决的是 **「协议首部/地址结构里的多字节字段，在线路上和 sockaddr 里必须一致」**；不是指「IP 字符串 `192.168.1.1`」这种给人看的写法——那种先由 **`inet_pton`** 变成二进制网络序，再交给内核。

### 6. 易错（初学者）

| ❌ | ✅ |
|----|-----|
| `sin_port = 13;` 不写 `htons` | `sin_port = htons(13);` |
| 对 `inet_pton` 填好的 `sin_addr` 再 `htonl` | `inet_pton` 结果直接赋值 |
| 以为「小端机器上不用转」 | **只要进 sockaddr / 上网，端口就要网络序** |
| 混淆「主机名」和「二进制 IP」 | 1.2 用 **`argv[1]` 点分 IP + inet_pton**；域名见 1.3 **`getaddrinfo`** |

### 3. `connect(int fd, (SA *)&servaddr, sizeof(servaddr))`

| 项 | 说明 |
|----|------|
| **`SA`** | `#define SA struct sockaddr` — **通用地址指针**，兼容不同协议地址结构 |
| **强制转换** | `(SA *)&servaddr` — **BSD Socket 标准写法** |
| **失败** | **不能**对同一 sockfd **再次 connect** → 须 **`close` 旧 fd → 重新 `socket` → 再 connect** |

### 4. `read(sockfd, buf, MAXLINE)` 循环读取

| 要点 | 说明 |
|------|------|
| **TCP 字节流** | **无报文边界** — 服务端一次发 26 字节，内核可能 **10+16** 分次交付 |
| **规范** | `while ((n = read(sockfd, buf, MAXLINE)) > 0) { … }` |
| **返回 0** | 对端 **close**，收到 **FIN**，数据流结束 |
| **返回 < 0** | 出错（查 `errno`） |

→ 封装重试：[Ch 3.9 readn/writen](../Chapter03_SocketProgramIntro/3.9_Readn_Writen_Readline.md)

## 四、高频易错点汇总

| # | ❌ 错误 | ✅ 规范 |
|---|--------|--------|
| 1 | 单次 `read` 读完全部数据 | **`while` 循环** — TCP 流式**无包边界** |
| 2 | `memset` 填充值与长度写反 | UNP 用 **`bzero`** 清零地址结构体 |
| 3 | `connect` 失败后再次 `connect` 同一 fd | **`close` → 新 `socket` → 再 connect** |
| 4 | 端口/IP 不做网络序转换 | 端口 **`htons`**；IP **`inet_pton`** |

## 六、完整源码逐行注释（图 1-5 · `daytimetcpcli.c`）

**作用**：与服务器建立 **TCP** 连接，读取 **Daytime（13 端口）** 返回的时间字符串，输出到 **stdout**。

→ 仓库主副本：[code/1.2_SimpleTimeClient/original_c/daytimetcpcli.c](./code/1.2_SimpleTimeClient/original_c/daytimetcpcli.c)（更长的 C 新手注释）· 镜像：[intro/daytimetcpcli.c](./intro/daytimetcpcli.c)

```c
#include    "unp.h"

int
main(int argc, char **argv)
{
    int                 sockfd, n;
    char                recvline[MAXLINE + 1];  /* +1 预留字符串结束符 '\0' */
    struct sockaddr_in  servaddr;               /* IPv4 服务端地址结构 */

    /* 校验入参：必须传入 1 个 IP，例：./daytimetcpcli 127.0.0.1 */
    if (argc != 2)
        err_quit("usage: a.out <IPaddress>");

    /* ① 创建 TCP 套接字 */
    if ((sockfd = socket(AF_INET, SOCK_STREAM, 0)) < 0)
        err_sys("socket error");

    bzero(&servaddr, sizeof(servaddr));         /* 地址结构清零，避免残留脏数据 */
    servaddr.sin_family = AF_INET;
    servaddr.sin_port   = htons(13);            /* Daytime 标准 13 端口，主机序→网络大端 */
    if (inet_pton(AF_INET, argv[1], &servaddr.sin_addr) <= 0)
        err_quit("inet_pton error for %s", argv[1]);  /* 点分十进制 IP → 二进制网络 IP */

    /* ② connect：内核完成 TCP 三次握手 */
    if (connect(sockfd, (SA *) &servaddr, sizeof(servaddr)) < 0)
        err_sys("connect error");

    /* ③ 循环读：TCP 字节流无边界，必须 while 分次收取 */
    while ((n = read(sockfd, recvline, MAXLINE)) > 0) {
        recvline[n] = 0;        /* 手动追加 '\0'，fputs 需要 C 风格字符串 */
        if (fputs(recvline, stdout) == EOF)
            err_sys("fputs error");
    }
    /* read<0：读出错；read=0：对端 close、收到 FIN，循环正常退出 */
    if (n < 0)
        err_sys("read error");

    exit(0);    /* 进程退出，OS 回收 fd 并发 FIN；生产仍建议显式 close(sockfd) */
}
```

<a id="ch1-2-exam-detail"></a>

### 源码核心考点（逐条）

| # | 代码点 | 要点 |
|---|--------|------|
| 1 | **`recvline[MAXLINE + 1]`** | `read` 只填**二进制字节、不带 `\0`**；读到 `n` 字节后 **`recvline[n]=0`**，`fputs` 才能当字符串输出 |
| 2 | **`htons(13)`** | 端口必须 **主机序→网络大端**；**`inet_pton`** 内部已处理 IP 字节序，**勿再** `htonl` → [§二附](#ch1-2-byteorder) |
| 3 | **`(SA *)&servaddr`** | `SA` = `#define SA struct sockaddr`；`connect` 用**通用地址指针**，多协议 API 统一 |
| 4 | **`while (read…>0)`** | Daytime 可能一次 26B，内核或拆成 **10+16** 两次交付；**须循环直到 `read==0`**（对端 FIN） |
| 5 | **`connect` 失败** | 返回 -1 时**不能**同一 `sockfd` 再 `connect` → **`close` → 新 `socket` → 再试** |

> `inet_pton` 第二参数是 **`argv[1]`**（IP 字符串），不是 `argv` 本身。

## 七、程序运行逻辑时序

```text
入参 IP → socket 创建 fd → 组装 servaddr（IP + htons(13)）→ connect 三次握手 →
循环 read 从 TCP 接收缓冲区取数据 → 补 '\0' → fputs 打印 →
read=0（服务端发 FIN）→ exit（内核关闭 fd）
```

## 九、个人学习总结

1. **五步法背熟**：`socket` → 填 **`sockaddr_in`（htons + inet_pton）** → `connect` → **`while read`** → `exit`/`close`。
2. **网络序**：端口手写整数必 **`htons`**；IP 字符串用 **`inet_pton`**。
3. **TCP 是字节流**：不要假设一次 `read` 读完；**`recvline[n]=0`** 是为 C 字符串，不是协议要求。
4. **健壮性缺口（故意留给后章）**：裸 `read` 未处理 **`EINTR`** → [Ch 3.9 readn](../Chapter03_SocketProgramIntro/3.9_Readn_Writen_Readline.md)；协议/双栈 → [1.3](./1.3_ProtocolIndependence.md)、[Ch 11 getaddrinfo](../../2_AdvancedSkill/Chapter11_Name_Address_Convert/study.md)。
5. **可自练拓展**：命令行传端口、`connect` 超时、IPv6 / `getaddrinfo` 版客户端。

**30 字背诵**：建套接字、组地址网络序、连接、循环读到零、退出关连接。
