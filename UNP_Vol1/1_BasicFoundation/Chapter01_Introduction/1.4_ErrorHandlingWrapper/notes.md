# 1.4 错误处理：包裹函数

## 核心知识点

系统调用与库函数都可能失败，必须检查返回值。本书用 **包裹函数（Wrapper Function）** 统一处理错误，避免检查代码淹没业务逻辑。

## 关键函数与结构体

| 机制 | 说明 |
|------|------|
| **命名** | 底层函数首字母大写，如 `socket` → `Socket` |
| **逻辑** | 内部调用原函数；返回值 `< 0`（或其它错误）→ `err_sys` 打印并 `exit` |
| **`errno`** | Unix 函数出错时置正数错误码；`err_sys` 据此输出（如 "Connection timed out"） |
| **`errno` 有效性** | **仅当函数返回错误**（通常 -1）时才有意义；成功时不保证为 0 |

## 易错点与坑点

| 场景 | 要点 |
|------|------|
| **多线程** | `errno` 常为宏或**线程局部存储**，非简单全局变量 |
| **Pthread** | POSIX 线程函数出错**不设置 `errno`**，错误码作为**返回值**返回 → 需单独处理 |

## 个人学习总结

> 💡 可拓展：常见 `errno`（`EINTR`、`EAGAIN`、`ECONNRESET`）及触发场景。
