# 1.1 数据包分析与数据包嗅探器

> 本章：[chapter-summary.md](./chapter-summary.md) · 全书：[../README.md](../README.md)

**核心主旨**：明确数据包分析的基础概念及其实现工具，阐述数据包嗅探器从网络线缆获取数据并转化为可分析信息的完整工作流程。

## 核心知识点

### 关键定义

| 术语 | 说明 |
|------|------|
| **数据包分析**（Packet Analysis / Protocol Analysis） | 又称数据包嗅探、协议分析；**捕获并解析**线路上传输的数据，弄清网络上真实在传什么，用于排性能、安全等问题。 |
| **数据包嗅探器**（Packet Sniffer） | 执行上述过程的工具；在网络介质上**捕获原始传输数据**。 |

### 嗅探器三步工作流

```text
线缆原始比特 → [1 收集] → [2 转换] → [3 分析] → 可读结论
```

1. **收集（Collect）**
   - 从网线/无线介质抓取**二进制原始数据**。
   - 常将网卡设为**混杂模式（Promiscuous Mode）**：接收**整个网段**上的帧，而不只是「发给自己 MAC」的单播。
2. **转换（Convert）**
   - 把二进制变成人可读形式；命令行工具（如 tcpdump）常止步于此层——**基础解析**后交给人工继续读。
3. **分析（Analyze）**
   - 识别、校验**各层协议**；提取字段（IP、端口、标志位等），形成排障结论。Wireshark 等 GUI 工具主要价值在这一步。

### 工具横向对比（速记）

| 工具 | 强项 | 适用 |
|------|------|------|
| **Wireshark** | 图形化解码、过滤器、协议树、统计 | 日常排障、学习协议 |
| **tcpdump / tshark** | 脚本化、服务器无 GUI、轻量抓包 | 生产机、自动化、先抓后分析 |

> 跨平台：二者在 Linux / macOS / Windows 均可使用；大流量场景可先 tcpdump 落盘，再 Wireshark 离线打开 `.pcap`。

## 抓包/实操记录

| 步骤 | 操作 |
|------|------|
| 混杂模式 | Wireshark：捕获选项 → 勾选对应接口的混杂模式（部分驱动/无线网卡受限） |
| 验证三步 | 抓一段浏览网页流量 → 看 **Frame**（收集）→ **协议树展开**（转换+分析） |
| 过滤器入门 | 只看 HTTP：`http`；只看某 IP：`ip.addr == x.x.x.x` → 详见 [cheatsheet/notes.md](../cheatsheet/notes.md) |

## 疑问与总结

- **嗅探 vs 分析**：嗅探强调「抓到」；分析强调「读懂协议与行为」——Wireshark 覆盖后两步，tcpdump 偏前两步。
- **合法边界**：仅在自己有权管理的网络或实验环境抓包；生产网需合规授权。
