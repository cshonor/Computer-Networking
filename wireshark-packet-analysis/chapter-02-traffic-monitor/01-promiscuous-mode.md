# 2.1 混杂模式

> 本章：[chapter-summary.md](./chapter-summary.md) · 全书：[../README.md](../README.md) · 回顾：[§1.1 嗅探器三步](../chapter-01-network-basics/01-what-is-packet-analysis.md)

**核心主旨**：数据包嗅探的底层硬件/驱动前提——混杂模式的定义，以及为何跨主机分析必须开启它。

## 核心知识点

### 混杂模式（Promiscuous Mode）

| 状态 | 网卡行为 |
|------|----------|
| **正常模式** | 收到目的 MAC **不是本机** 的帧 → 驱动**直接丢弃**，不占 CPU 处理上层协议 |
| **混杂模式** | 强制接收并向上提交**线路上嗅到的所有帧**（仍受交换机端口转发范围限制，见 §2.3） |

### 广播域与可见流量

在局域网（同一广播域）内：

| 流量类型 | 不开启混杂 | 开启混杂 |
|----------|------------|----------|
| 广播（ARP 等） | ✅ 可见 | ✅ 可见 |
| 发往本机单播 | ✅ 可见 | ✅ 可见 |
| **其他主机之间单播** | ❌ 不可见 | ✅ 可见（前提是帧能到达本端口） |

> 不开启混杂时，嗅探器**无法分析** A↔B 的通信细节，只能看到广播 + 与自己相关的包。

### 权限门槛

| 系统 | 典型要求 |
|------|----------|
| Windows | **管理员** |
| Linux / macOS | **root** 或 `CAP_NET_RAW` / `CAP_NET_ADMIN` |

Wireshark：安装 Npcap/WinPcap 时勾选「以管理员启动」；Linux 可将用户加入 `wireshark` 组并配置 `dumpcap` 权限。

**合规**：无法在系统上**合法取得**相应权限时，不应强行嗅探。

## 抓包/实操记录

| 平台 | 开启混杂（示例） |
|------|------------------|
| Linux | `sudo ip link set eth0 promisc on`；关闭：`promisc off` |
| 旧式 | `ifconfig eth0 promisc` |
| Wireshark | 捕获选项 → 勾选对应接口 **Promiscuous mode** |

**兼容性**：部分无线网卡、虚拟网卡、云主机**不支持或受限**混杂；抓不到他人单播时先查驱动/虚拟化文档，而非只调过滤器。

## 疑问与总结

- 混杂模式 ≠ 一定能看到全网流量；**交换机**仍可能不把他人单播送到你的端口（需镜像/TAP/Hub/ARP 等手段，见 §2.3）。
- 与 [§1.3 流量分类](../chapter-01-network-basics/03-traffic-classification.md) 对照：广播人人收得到，单播跨主机分析才强依赖混杂。
