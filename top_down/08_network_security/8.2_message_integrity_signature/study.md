# 8.2 消息完整性与数字签名

> 章级精读：[§8.3 完整性/签名](../study.md#ch8-3) · [§8.4 鉴别](../study.md#ch8-4)

## 一、消息完整性的挑战

如何证明数据在传输过程中没有被篡改？

## 二、哈希函数（Hash Function）

- 核心特点：任意长度的输入，得到固定长度的输出（摘要）
- 关键特性：单向性、抗碰撞性
- 典型算法：MD5（已不安全）、SHA-1（已不安全）、**SHA-256**（主流）
- 用途：生成消息摘要，用于完整性校验

## 三、消息认证码 MAC（Message Authentication Code）

- 核心原理：基于对称密钥，对消息和密钥进行哈希运算，生成 MAC 值
- 典型算法：**HMAC**（基于哈希的消息认证码）
- 作用：验证消息完整性和发送方身份真实性（需共享密钥）
- 缺点：无法提供不可否认性，双方共享同一密钥，无法区分谁发送的数据

## 四、数字签名（Digital Signature）

- 核心原理：发送方用自己的**私钥**对消息摘要进行加密，形成数字签名
- 接收方用发送方的**公钥**解密签名，验证摘要是否匹配
- 核心特性：
  1. 完整性：消息未被篡改
  2. 身份认证：发送方身份真实
  3. 不可否认性：发送方无法否认自己发送过数据
- 典型算法：RSA 签名、**ECDSA**（椭圆曲线数字签名）

## 五、数字证书与 PKI

- **数字证书**：由 CA（证书权威机构）签发，包含用户公钥和身份信息，证明公钥的合法性
- **PKI**（公钥基础设施）：管理数字证书的体系，实现公钥的安全分发和验证

## 六、本节核心考点

- 哈希函数、MAC、数字签名三者的区别与联系
- 数字签名的三大特性：完整性、身份认证、不可否认性
