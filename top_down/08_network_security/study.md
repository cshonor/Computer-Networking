# 第8章：计算机网络中的安全

安全不是事后可插拔的模块，而是贯穿各层的**属性**：需求常由应用定义（不可抵赖、隐私），实现依赖**TLS**、**IPsec**、鉴别与运行期机制（防火墙、IDS）等协同。在 IoT、5G 与云原生环境下，传统物理边界弱化，更需在协议设计与运维中贯彻**最小权限**与**深度防御**。

<a id="ch8-1"></a>

## 8.1 什么是网络安全

### 1. 核心属性

- **机密性（Confidentiality）**：仅预期接收方能理解内容；依赖算法与**密钥管理**。  
- **报文完整性（Message Integrity）**：防篡改；即使加密，也可能被恶意改密文块，故需完整性机制。  
- **端点鉴别（End-point Authentication）**：确认对端身份；防 **MITM** 的第一道关。  
- **运行安全性（Operational Security）**：防火墙、IDS/IPS、策略与可见性，维持边界与可用性。

### 2. 攻击者能力（模型）

可监听、注入、篡改、**重放**、**IP 欺骗**等；设计协议时按威胁模型假设对手能力。

→ **分层典型攻击一页背诵**：[layer-attacks-cheatsheet.md](./layer-attacks-cheatsheet.md)（ARP/SYN/HTTP 劫持等与 [§6](../06_link_layer_and_lan/study.md)/[§3](../03_transport_layer/study.md)/[§2](../02_application_layer/study.md) 对齐）

### 3. 工程避坑：加密 ≠ 鉴别

仅有加密不能防止**重放**：若捕获加密转账请求且无 **Nonce/时间窗/序号** 等鉴别，服务器可能重复执行。需**鉴别 + 防重放** 与机密性配合。

## 8.2 密码学原理

密码学为不安全信道提供可证明或可论证的数学约束；工程上要在**计算开销**与**安全强度**间折中。

### 1. 对称密钥体系

- **流密码 vs 分组密码**：现代互联网主体为**分组密码**（如 **AES**）配合模式；流密码仍有特定场景。  
- **AES**：取代 DES/3DES；常见硬件加速（如 **AES-NI**）。  
- **模式**：  
  - **ECB**：相同明文块 → 相同密文块，**泄露模式**，生产环境禁用。  
  - **CBC**：链接 IV 与前块密文；**IV 需不可预测/随机**（依标准与场景），否则有已知攻击面。

### 2. 公钥体系（RSA 直觉）

基于**大整数分解困难性**等假设（教学构造）：

1. 选大素数 **p, q**，**n = pq**  
2. **φ(n) = (p−1)(q−1)**  
3. 选 **e** 与 φ(n) 互素，求 **d** 使 **ed ≡ 1 (mod φ(n))**  
4. 加密 **c = m^e mod n**，解密 **m = c^d mod n**

（工程常用 **RSA-OAEP** 等填充，避免教科书 RSA 直接用于明文。）

### 3. 混合加密

| 维度 | 对称（AES） | 公钥（RSA/ECC） |
|------|-------------|-----------------|
| 速度 | 快，适合大批量数据 | 慢，模幂/椭圆曲线点乘贵 |
| 密钥分发 | 难 | 公钥可公开分发 |
| PFS | 依赖会话密钥协商方式 | 可与 **(EC)DHE** 等结合实现 |

实践：**用公钥/握手协商会话密钥，再用对称算法保护记录层**。

## 8.3 报文完整性与数字签名

### 1. 密码散列（Hash）

**单向**、**抗碰撞**；**MD5、SHA-1** 已不应作为安全依赖；使用 **SHA-256** 及以上并配合正确构造（HMAC、签名等）。

### 2. MAC

单纯 **Hash(m)** 不能防篡改（攻击者可同时替换 **m** 与哈希）。**MAC** 引入共享秘密，如 **HMAC** 等标准结构。  
**禁止**自造 `Hash(Key ‖ Message)` 之类拼接——易受**长度扩展攻击**等；用 **HMAC-SHA256** 等。

### 3. 数字签名与 PKI

- **签名**：私钥对摘要签名，公钥验证。  
- **CA / 证书链**：把身份与公钥绑定，解决「最初信任谁」的问题。

<a id="ch8-4"></a>

## 8.4 端点鉴别

### 重放与鉴别演进

明文口令可被嗅探；仅靠源 IP 可被**欺骗**。

### Nonce（不重数）

服务器发一次性随机挑战 **R**，客户端用共享秘密或私钥响应；旧报文因 **R** 变化而失效。

### MITM 与 TLS

鉴别若不经**证书/信任锚**绑定公钥，攻击者可在 A、B 间各建一条连接做双向代理。**架构建议**：敏感鉴别放在 **TLS 信道 + 证书校验** 之上。

<a id="ch8-5"></a>

## 8.5 安全电子邮件

邮件是**存储-转发**，收发常不同步，安全常需落在**报文本身**（**PGP / S-MIME**），而非仅传输层 TLS（传输 TLS 仍重要，但不足以覆盖多 hop 存储）。

### PGP（概念结构）

混合加密典型形态：

- 用接收方**公钥加密会话密钥**；  
- 用发送方**私钥对摘要/报文签名**；  
- 用会话密钥**对称加密**正文。

### Web of Trust

PGP 传统上可用**用户互签**建立分散信任，与中心化 **PKI** 不同；企业场景常见 **S-MIME + 企业 CA**。

<a id="ch8-6"></a>

## 8.6 使 TCP 连接安全：TLS

**TLS**（前身 SSL）保护 Web 等大量流量；**TLS 1.3** 删减不安全套件，握手常 **1-RTT**（带会话恢复可更短，**0-RTT** 有重放权衡）。

### TLS 1.3 握手（简化）

1. **ClientHello**：算法、**(EC)DHE 公钥**、随机数等。  
2. **ServerHello + 证书与签名**：服务器鉴别；**DHE** 提供 **PFS**（长期私钥泄露难解密历史流量，仍依赖实现与密钥生命周期）。  
3. **Finished**：确认握手完整性。

### 密钥派生：方向分离的设计意图

**TLS 1.2** 及更早常从主密钥经 PRF 派生**客户端写加密密钥 / 服务器写加密密钥 / 各自 MAC 密钥**等，体现**方向分离**与防**反射**类问题的工程习惯。

**TLS 1.3** 使用 **HKDF** 从共享秘密派生多层密钥材料，记录层普遍采用 **AEAD**（如 **AES-GCM、ChaCha20-Poly1305**）——**完整性与机密性由 AEAD 统一提供**，不再以「独立 MAC 密钥」形态出现；教学上仍可用「多路派生、方向分离」理解**密钥隔离**思想。

## 8.7 网络层安全性：IPsec 与 VPN

**IPsec** 可对上层应用**透明**地提供安全关联（视部署模式）。

### ESP 与模式

| 模式 | 结构直觉 | 典型用途 |
|------|----------|----------|
| 传输模式 | 原 IP 头 + ESP + 载荷 + ESP 尾（示意） | 主机到主机 |
| 隧道模式 | **新 IP 头** + ESP + **内层 IP 包** + … | **站点 VPN**、网关封装 |

**ESP** 可提供机密性与完整性；**AH** 偏重认证（现代组合视需求而定）。

### SA 与 IKE

**SA（安全关联）**：单向的逻辑连接，约定算法与密钥材料。**IKE** 负责协商与刷新 SA。

<a id="ch8-8"></a>

## 8.8 安全无线局域网与 4G/5G 蜂窝网络

### Wi‑Fi：WEP → WPA2 → WPA3

**WEP** 因 IV 空间与设计问题易被破解。**WPA3** 引入 **SAE** 等，改善弱口令下的离线字典攻击面（具体以标准与实现为准）。

### 4G/5G 与 AKA

蜂窝网采用 **AKA** 等机制做**双向鉴别**与密钥协商：网络认证用户，**UE 也验证网络**，可降低部分伪基站风险；现实威胁与攻防仍在演进，不能视为绝对免疫 **IMSI catcher**。

### 工程避坑

**隐藏 SSID**、**MAC 过滤**属于**隐匿式安全**，专业工具易绕过；应使用**强认证与加密（如 WPA3）**、证书/802.1X 等企业机制。

<a id="ch8-9"></a>

## 8.9 运行安全性：防火墙与 IDS

加密与鉴别不能替代**运行时监控**与**边界策略**。

### 防火墙演进

- **无状态包过滤**：五元组规则，易被状态不一致报文戏弄。  
- **状态检测（Stateful）**：跟踪 **TCP 状态机** 等，拒绝非法序列。  
- **应用层网关 / DPI**：对 HTTP、DNS 等做策略与检测。

### IDS / IPS

- **基于签名**：匹配已知恶意特征。  
- **基于异常/行为**：统计与机器学习发现偏离基线（如 DDoS 前兆）；注意误报/漏报权衡。

<a id="ch8-10"></a>

## 总结

网络安全是**数学、协议与运维**的系统工程：**边缘状态防火墙 + 强制现代 TLS + 多因素鉴别 + 持续监控** 构成常见纵深。安全不是一次性交付，而是与威胁共同演进的持续过程。
