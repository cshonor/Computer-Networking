# 3.3 UDP 协议

> 章级精读：[../study.md#ch3-3](../study.md#ch3-3) · 首部图：[四字段](../assets/udp_header_fields.png) · 伪首部/封装：[章级 §3.3](../study.md#ch3-3-header)

## 本节核心目标

透彻理解 UDP **极简头部、无连接、不可靠、低时延** 的特性与工作方式。

---

## 一、UDP 基本概念

**UDP（User Datagram Protocol，用户数据报协议）**  
传输层协议，**无连接、不可靠、面向数据报**；**RFC 768**；IP 协议号 **17**。

---

## 二、UDP 头部：仅 8 字节（必考）

UDP 报文段首部固定 **8 字节**，结构极简：

![UDP 首部：源/目的端口、长度、检验和 + 变长数据](../assets/udp_header_fields.png)

<a id="ch3-3-diagram"></a>

### 读图

| 位宽标记 | 含义 |
|----------|------|
| **0 / 15 / 16 / 31** | 一行 **32 bit（4 字节）** |
| **第一行** | **源端口**（0–15）｜**目的端口**（16–31），各 **16 bit** |
| **第二行** | **UDP 长度**（0–15）｜**UDP 检验和**（16–31），各 **16 bit** |
| **下方大块** | **数据**（变长）→ 整块为 **UDP 用户数据报** |

| 字段 | 宽度 | 作用 |
|------|------|------|
| **源端口** | 2 B | 发送进程 |
| **目的端口** | 2 B | 接收进程（[分用](../3.2_multiplexing_demultiplexing/study.md#ch3-2-exam)） |
| **长度** | 2 B | **首部 + 数据** 总字节数 |
| **检验和** | 2 B | 差错检测（IPv4 可发 **0** 表示未算；IPv6 **强制**；错包常**丢弃**） |

对比：**TCP 首部至少 20 字节**（可至 60 B），开销大得多。

→ 伪首部、IP 封装详读：[章级 #ch3-3-header](../study.md#ch3-3-header)

## 三、核心特性（4 条必背）

1. **无连接**  
   无需握手，直接发；不维护连接状态 → 服务器**并发能力强**。

2. **不可靠交付**  
   - 无确认（无 ACK）  
   - 无重传（丢包不补）  
   - 无排序（可能乱序）  
   - 无流量 / 拥塞控制  
   → **尽最大努力交付**，不保证一定到达。

3. **面向数据报**  
   应用写 **一次** → 一个 UDP 包；**保留消息边界**，不拆分、不合并。

4. **开销极小、时延极低**  
   首部 8 B + 无握手 / 无重传 → **速度快、实时性强**。

---

## 四、优点与缺点

### 优点

- **超低时延**：适合实时场景  
- **轻量高效**：头部小、机制简单  
- **高并发**：无连接，服务器负载低  
- **支持多播 / 广播**：一对多通信  

### 缺点

- **不可靠**：丢包、乱序、重复  
- **不适合大文件可靠传输**：需应用自建可靠性  
- **应用层可能要自己做** ACK、重传、排序  

---

## 五、典型适用场景（4 类必背）

| 场景 | 例子 |
|------|------|
| **语音通话** | 微信 / 电话 VoIP |
| **视频直播 / 会议** | 抖音 / Zoom |
| **在线游戏** | MOBA / FPS |
| **DNS、DHCP、流媒体** | 查询小、可重试或容忍丢包 |

一句话：**实时 > 可靠** 时用 UDP。

## 六、UDP 与 TCP 快速对比（考试常考）

| 特性 | **UDP** | **TCP** |
|------|---------|---------|
| 连接 | 无连接 | 面向连接（三次握手） |
| 可靠性 | 不可靠 | 可靠（ACK、重传、排序） |
| 头部长度 | **8 B** 固定 | **20–60 B** |
| 数据形态 | **报文**（有边界） | **字节流** |
| 时延 | 极低 | 较高 |
| 流控 / 拥塞 | 无 | rwnd + cwnd |
| 广播 / 多播 | 支持 | 不支持 |
| 适用场景 | 实时音视频、游戏、DNS | 网页、邮件、文件传输 |

**易错**：UDP **有检验和**（不是“完全不检错”），但**不负责重传**。
