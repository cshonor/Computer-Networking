# 20.1 为什么要重定向

> 本章：[chapter-summary.md](./chapter-summary.md#ch20-1) · 全书：[../README.md](../README.md) · [ch18 分布式托管](../chapter-18-web-hosting/chapter-summary.md)

## 本节核心目标

理解重定向与负载均衡要解决的三大需求：**可靠、低时延、省带宽**。

---

<a id="ch20-1-goals"></a>

## 三大核心需求

| 需求 | 重定向如何满足 |
|------|----------------|
| **可靠执行 HTTP 事务** | 内容多副本，单点故障时仍有可用节点 |
| **最小化时延** | 导向**更近**的副本 |
| **节约带宽** | 分散流量，减轻拥塞 |

---

<a id="ch20-1-distributed"></a>

## 分布式部署

Web 内容常分布在**多个地理位置**；一处宕机，其他位置仍可服务。

---

<a id="ch20-1-lb"></a>

## 重定向与负载均衡

- **重定向**：帮客户端找到「最佳」分布式内容的一组技术  
- **负载均衡**：把入站请求摊到一组服务器  
- 二者**高度重叠**：多数重定向部署含 LB；多数 LB 内含重定向逻辑
