# 20.8 缓存阵列路由协议（CARP）

> 本章：[chapter-summary.md](./chapter-summary.md#ch20-8) · [20.7 ICP](./07-icp.md)

## 本节核心目标

掌握 **CARP** 如何用 **URL 散列**把多代理合成**单一逻辑缓存**，消除 ICP 冗余。

---

<a id="ch20-8-hash"></a>

## 散列映射

对 URL 做散列 → **唯一**映射到集群中某台代理。

- **一次计算**定位置，无需广播 ICP 查询  
- **负载因子**调节各机承担对象的概率  

---

<a id="ch20-8-pros-cons"></a>

## 优劣

| 优点 | 缺点 |
|------|------|
| 无 ICP 查询风暴 | **不支持**兄弟缓存关系 |
| 减少对象重复，**总容量↑** | 任一节点故障 → **重算散列表** |
| 负载可统计均衡 | 重配置会**失效**部分既有缓存 |

---

## 拓展（预留）

- **一致性哈希**：节点增减时只迁移少量键，缓解 CARP 大规模失效
