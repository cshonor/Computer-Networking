# 5.5 第二步——接收请求报文

> 本章：[chapter-summary.md](./chapter-summary.md#ch05-5) · [ch03 报文](../chapter-03-http-message/chapter-summary.md)

## 本节核心目标

理解**读请求**的解析规则，以及四种**并发 I/O 架构**。

---

<a id="ch05-5-parse"></a>

## 一、解析规则

1. 读**请求行**（方法、URI、版本）  
2. 读首部至 **空行（CRLF）**  
3. 若有 body，按 **`Content-Length`**（或 chunked）读取  

内部常把首部放入**哈希表**，body 用指针+长度零拷贝引用。

---

<a id="ch05-5-arch"></a>

## 二、四种 I/O 结构（重点）

| 模型 | 行为 | 适用 |
|------|------|------|
| **单线程** | 一次一个请求，其余阻塞 | 仅调试（type-o-serve 类） |
| **多进程/多线程** | 每连接一线程/进程 | 需**限制最大并发**，否则内存爆 |
| **复用 I/O** | 监视多连接，**有事件才处理** | select/poll/**epoll** |
| **复用 + 多线程** | 每线程管一批连接 | **Nginx** 等高性能首选 |
