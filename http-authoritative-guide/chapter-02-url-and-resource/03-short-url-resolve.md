# 2.4 各种令人头疼的字符

> 本章：[chapter-summary.md](./chapter-summary.md#ch02-4) · [2.2 语法](./02-url-syntax.md) · 文件名为历史目录名（原「短URL」占位）

## 本节核心目标

理解 URL **字符集限制**、**百分号编码**、保留/不安全字符及编解码原则。

---

<a id="ch02-4-charset"></a>

## 一、URL 字符集

- URL 须用**较小、通用、安全**的字母表传输  
- 避免在 **SMTP** 等协议中被破坏或剥掉特殊字符  
- 历史上常用 **US-ASCII**

---

<a id="ch02-4-encoding"></a>

## 二、编码机制（Escape）

**转义**：`%` + **两个十六进制**（该字符码）

| 字符 | 编码示例 |
|------|----------|
| 空格（32） | `%20` |
| 中文等非 ASCII | 按所用编码（常 UTF-8）逐字节 `%xx` |

---

## 三、保留字符 vs 不安全字符

| 类型 | 例子 | 作为数据出现时 |
|------|------|----------------|
| **保留**（语法用） | `/` `?` `#` `&` `;` | 必须 **% 编码** |
| **不安全** | 空格 `<>` `{}` … | 必须编码 |

---

## 四、谁编码、谁解码

| 原则 | 说明 |
|------|------|
| **最佳编码点** | 最初拿到 URL 的**源端客户端**（浏览器、表单提交） |
| **接收端** | 使用前必须**解码** |
| **过度编码** | 对安全字符也编码虽常合法，但可能让过滤器**匹配失败**（绕过风险） |

---

## 易错

- **`encodeURI`**：保留 `?#/` 等用于整 URL  
- **`encodeURIComponent`**：用于 **query 参数值** 等组件内部  
- **IDN / Punycode**：国际化域名显示中文、实际 `xn--…` 形式
