# 4.7 关闭连接

> 本章：[chapter-summary.md](./chapter-summary.md#ch04-7) · [4.5 持久连接](./05-persistent-connection.md) · [ch03 实体长度](../chapter-03-http-message/06-entity.md)

## 本节核心目标

掌握 **截尾检测**、**幂等重试** 与 TCP **半关闭** 的正确姿势。

---

<a id="ch04-7-truncation"></a>

## 一、检测截尾（Content-Length）

服务器可能**随时关闭空闲连接**。因此：

- 每条 HTTP 响应应有精确 **`Content-Length`**（或 `chunked` 等明确结束方式）  
- 若**无长度信息就断连**，客户端/代理应**质疑 body 是否完整**  
- **缓存代理不得缓存**此类不确定长度的响应

---

<a id="ch04-7-retry"></a>

## 二、重试与幂等性

| 情况 | 客户端行为 |
|------|------------|
| 非错误性断连 | 可**重开连接重试** |
| **非幂等**（如 POST 下单） | **禁止自动重试** |

→ 浏览器「重新提交表单」警告的来源。

---

<a id="ch04-7-halfclose"></a>

## 三、正常关闭：半关闭

| API | 效果 |
|-----|------|
| `close()` | **全关闭** 读+写 |
| `shutdown()` | **半关闭** 一侧 |

**易错**：若先关**本端输入**，对端仍发数据 → 对端可能收到 **RST（Connection reset by peer）**，**清空**尚未读取的合法响应。

**推荐顺序**：

1. **半关闭输出**（FIN）  
2. 读对端直到对端也关闭输出  
3. 完全结束连接
