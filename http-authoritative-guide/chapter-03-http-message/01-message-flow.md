# 3.1 报文流

> 本章：[chapter-summary.md](./chapter-summary.md#ch03-1) · 全书：[../README.md](../README.md) · 连接：[ch04](../chapter-04-connection-management/chapter-summary.md)

## 本节核心目标

理解 HTTP 报文在客户端、服务器、代理之间的**流动方向**术语：**流入/流出**、**上游/下游**。

---

<a id="ch03-1-in-out"></a>

## 一、流入与流出（Inbound & Outbound）

| 术语 | 含义 |
|------|------|
| **流入（Inbound）** | 报文**朝向源端服务器**流动（请求进入服务器侧） |
| **流出（Outbound）** | 事务完成后，报文**流回用户 Agent**（响应回到客户端侧） |

用于描述**事务处理方向**，偏「业务视角」。

---

<a id="ch03-1-up-down"></a>

## 二、上游与下游（Upstream & Downstream）

| 规则 | 说明 |
|------|------|
| **下游（downstream）** | **请求报文、响应报文**都沿**下游**传递 |
| **上游（upstream）** | 在任意节点上，**发送者**始终在**接收者的上游** |

**逻辑脉络**

```text
客户端 --请求↓--> 代理 --↓--> 服务器
客户端 <--响应↓-- 代理 <--↓-- 服务器
```

请求、响应都是**向下游**走；谁发谁就是对方的**上游**。

---

## 三、易错（考点）

**不能**用「报文是发给服务器还是客户端」**固定**判断上下游：

| 报文类型 | 例子 |
|----------|------|
| **请求** | 代理1 在代理3 的**上游**（代理1 先发请求给代理3） |
| **响应** | 代理1 在代理3 的**下游**（响应从代理3 回到代理1） |

**一句**：上下游只与**当前这条报文的发送者/接收者**有关，**随请求/响应反转**。
