# 3.3 方法

## 本节核心目标

掌握 HTTP **标准方法**的语义及**扩展方法**、代理对未知方法的处理原则。

---

<a id="ch03-3-standard"></a>

## 一、标准方法

| 方法 | 语义 |
|------|------|
| **GET** | 从服务器**取**命名资源（最常用） |
| **HEAD** | 与 GET 类似，但响应**只有首部、无实体主体** → 探测类型/是否存在/是否修改而不下载正文 |
| **PUT** | **写入**文档：用请求体在 URL 处**创建**或**整体替换**已有资源 |
| **POST** | 向服务器**提交数据**（如 HTML 表单、网关处理） |
| **TRACE** | 追踪：服务器在响应体中**回显**收到的请求（经代理修改可见） |
| **OPTIONS** | 询问服务器/资源**支持哪些方法** |
| **DELETE** | 请求删除 URL 命名的资源 |

---

## 二、扩展方法

- HTTP **可扩展**；规范外方法合法，如 **WebDAV**：`LOCK`、`MKCOL`、`COPY`、`MOVE` 等。

| 原则 | 说明 |
|------|------|
| 未知方法 | 并非所有代理/服务器都理解 |
| 代理行为 | **对发送严、对接收宽**；无法安全转发 → **501 Not Implemented** |

---

## 三、易错

- **HEAD** 不是「轻量 GET 下载」的替代品做完整性校验——**没有 body**，不能靠 body 校验内容。  
- **PUT** 语义是**整资源替换**，局部更新在现代 API 常靠 **PATCH**（本书时代 PATCH 尚未普及，REST 笔记可另补）。

---

## 拓展（预留）

- **安全方法**（Safe）与**幂等**（Idempotent）：GET/HEAD 通常安全；GET/PUT/DELETE 通常幂等；POST 非幂等  
- RESTful API 设计与方法的对应关系
